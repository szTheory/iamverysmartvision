# Phase 5 Security Verification

**Verdict: SECURED.** All 42 threats are closed: 30 declared in the twelve plans (29 numbered mitigate threats plus the shared accept T-05-SC) and 12 audit-added threats (T-05-A01 to A12) for attacker-controlled input paths the plans did not register. Every mitigation was found in code, a named test, a named fault or a gate control at the cited location. There are no blocking and no non-blocking open threats. Six non-blocking observations are recorded under Residual risks; none maps to an open declared mitigation.

Register arithmetic: T-05-01 to T-05-29 are 29 mitigate threats (19 high, 10 medium); T-05-SC is 1 accept (low), repeated in each of the twelve plans; T-05-A01 to A12 are audit-added mitigate checks. Total 29 + 1 + 12 = 42.

Phase 5 adds this attack surface:
- ABI growth: the request grows a v2 tail (`psg_log`, `psg_log_capacity`), the report a v2 tail (`audio_*`, `psg_log_*`), `ivs_info` a v3 tail (audio grid, crystal, log record figures). A third output channel (audio) and a fourth span (the PSG write log) join the overlap lattice.
- Input path: 31 control bits per word, two connected controllers, derived pull-down masks read by the guest at `$01FE` and `$01FF`.
- PSG register file at `$01F0` to `$01FF` (guest-writable, masked), the lazy sample engine, the write log and its chain.
- Runner operator options `--audio-raw`, `--psg-log-out`, `--audio-wav`, `--wav-rate`, `--audio-out-max-bytes`; the IVSS `capture` and `assert psglog|audio` grammar (reasons 45 to 49); `tools/pcm` (reference converter and WAV writer); `tools/listen-demo.sh`; the runner-process watchdog (FIFO handshake).

## Residual risks (non-blocking, below `block_on: high` or without a declared mitigation)

1. **Failed runs leave created output files.** On a harness failure (cap reached, run refused, load failure) the files `--audio-raw`, `--psg-log-out` and `--audio-wav` that this run created stay on disk: empty, partial, or a 44-byte WAV with a zeroed header that is not a valid WAV. The report says `harness-fail` and the exit code is 14, so a script that checks the status is not misled, and the `refpcm.sha256` line is omitted when the WAV was not finished. Low.
2. **Operator-path trust carried from Phase 4.** `--update-golden` still uses `fopen(path, "w")` (truncates, follows symlinks) and content-directory symlinks are still followed (`hostio.c` read open has no `O_NOFOLLOW`). Neither changed in Phase 5. The new outputs are stricter (`O_EXCL`). Intermediate directory symlinks in an operator output path are followed, as for any shell redirection. Low.
3. **Watchdog orphan.** If the runner-process harness is killed with `SIGKILL` (not `HUP`, `INT` or `TERM`), its background watchdog subshell survives until its `sleep` ends (default 60 s, `IVS_RUNNER_PROCESS_TIMEOUT`) and then sends `TERM` to a recorded pid that may have been reused. Test-only, never in the shipped artifact. Low.
4. **No named control proves the measured-tier rule.** `claim-measured-without-d10` exists (`tools/check/kinds/claim.cmake:92-94`) and the auditor confirmed in a scratch copy that it fails for tier `measured-hardware`, but no directory under `tools/check/controls/` exercises it, so a regression of that one line would not be caught by `run-controls`. T-05-29 is closed because the mitigation is present and the other registry controls exist. Suggest adding a `claims-measured-without-d10` control. Low.
5. **TOCTOU on the event array is documented, not prevented.** The array is validated and then read once per event; a caller that changes it during the call has undefined behaviour by contract (`ivs_run.h`). The core stays memory safe if it does change: pin derivation reads only bits 0 to 30 of words 0 and 1 against a bounded table, and `controller_now` is a copy. Low.
