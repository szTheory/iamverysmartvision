## Phase Boundary

Both hand controllers become guest-visible machine input read through the PSG I/O ports, and the PSG becomes a real device that emits raw, cycle-stamped audio observations separate from any host PCM.

In scope: INP-01, INP-02, INP-03, API-03, AUD-01, AUD-02, and decision D7 (reference PCM location).
- Control-to-byte table as tier-tagged profile data, combination rule, guest read path at `$01FE/$01FF` (PSG R14/R15 as ports A/B).
- PSG register file at `$01F0-$01FF`, tone, noise, envelope, mixer, amplitude, reset, all rule values as tier-tagged profile data.
- Raw outputs: cycle-stamped register-write log and chip-rate sample stream, their buffers, digests, API growth and runner support.
- The slicing-invariance proof for input and audio, a second original diagnostic fixture, goldens, installed-consumer replay.
- A reference PCM converter outside the core (D7), operator-side only.

Not in scope: STIC, video, bus stalls (Phase 6), host audio output or any sound device, a shared library, an assembler dependency, ECS, IntelliVoice, claims about real hardware (D10) and runs with the owner's EXEC/GROM (D11).

## Implementation Decisions

### Controller input (INP-01, INP-02, INP-03, API-03)

- **D-01:** The Phase 4 logical input model stands unchanged (D-12..D-15 of Phase 4 and D6): one `uint32` per controller by PSG port, 31 control bits (`IVS_CTRL_*`, pinned by `data/expected/input-bits.ids`), bit 31 reserved, events applied at the first CPU-unit boundary whose start tick is `>= at_tick`. What changes: the words are now guest-visible. Invert `run.input.guest-invisible` deliberately (reviewed golden change) and update the `ivs_run.h` header comment.
- **D-02:** The control-to-byte table is 31 profile fields `input.control.<name>` (one line mask each, object form `{"lines": "$XX"}`), every one tagged `tier4-community`, conflict C16, plus `input.line_model = "ground-union"` (tag `inference`), `input.line_idle = "$FF"`, `input.port_output_read = "latch"` (tag `unknown-default-chosen`, C65). Values are the table in `05-DISCUSS-ctrl.md` P5-C1 (three tier-4 sources of one lineage agree on all 31; key 1 gives `$7E`, keys 1+9 give `$5A`, both reproduced). Generated into a build-tree `ivs_ctrl_lines[profile][31]` by a new fail-closed `cmake/IvsCtrlTable.cmake` (name set equals the `IVS_CTRL_*` set, values `01..FF`, known line model) with a `-DMUTATE=<control>` hook for a named fault. An independence literal `data/input/intv-2609-ntsc-family-p1.literal.txt` is written from sources only (pins, cleared bits, wiki value, byte, SRC locator, tag, conflict) and a gate probe checks pins-to-bits equals the cleared mask equals the wiki value equals the generated profile table. Pin map: pin 4=b0, 3=b1, 2=b2, 1=b3, 9=b4, 8=b5, 7=b6, 6=b7; the table is identical for both ports.
- **D-03:** Combination rule: `pins = 0xFF XOR OR(line masks of every set bit)`. The core never resolves a combination and accepts any subset of the 31 bits; SOCD and keypad exclusivity are host policy. Result classes and their tags are pinned in a new `data/expected/input-policies.ids` (single control, key+key, disc+side: `tier4-community`; key+disc, key+side, side+side: `inference` and guest-ambiguous; disc+disc, opposite directions, 3 or more: `unknown-default-chosen`, C63). A result that is only the model's definition is a policy row, never evidence.
- **D-04:** Guest path: `$01FE` = PSG R14 = port index 0, `$01FF` = R15 = port index 1 (index is by port, never player; C66 stays). R7 bit 6 selects port 0 direction and bit 7 port 1, with 1 = output (GI figure, tag `inference`, C73). Input mode low byte is `0xFF XOR port_pulldown[p]`; output mode returns the stored latch; a write always stores the latch. The upper byte is `$00` from a new device kind `memmap.device.psg8` fill (`unknown-default-chosen`, C64) re-pointed at the `psg_regs` region (`impl: real`). `port_pulldown[2]` lives in `ivs_memsys`, set only by an internal setter called from `ivs_input_apply`, restored on the refused-step take-back, zeroed at power-on, covered by the digest (MEM rows). Reads are pure, so `ivs_machine_peek` shows what a CPU read returns now. Unit-start granularity stays (C67). An unplugged port reduces to an idle port by inference.
- **D-05:** API-03 is met by the Phase 4 mechanism; Phase 5 strengthens its proof because guests can now branch on port reads (unit boundaries depend on the schedule): fuzz content B (constant-cycle poller, independent oracle computed from schedule, recorded unit starts and the literal table), fuzz content C (data-dependent loop, relational oracle against the one-unit-per-call reference at every boundary), the existing `run.fuzz.seed-01..08` seeds extended, the invariant `port_pulldown == derive(words)`, a C67 instruction-granularity test (event at `s`, `s+1`, `s-1` relative to a poll instruction's start tick), runner slicing `--slice-ticks 1` and `7` on the new `diag-ctrl-1` scenario, and an installed-consumer replay printing the peeked `$01FE` after the first event. No IVSS input-syntax change.
- **D-06:** Evidence tiers: single-control table claims `source-expectation`, standing `provisional`; the guest read-path claim `original-diagnostic`, `provisional`; API-03 `deterministic-repeatability` plus `installed-host-behavior`. No claim uses `measured-hardware` (D10). C14 stays open, C15 becomes `partial`, C16 stays open with its sources rewritten, C63/C64/C65 default policies updated, C66/C67 per their resolvers.

### PSG chip rules (AUD-01)

- **D-07:** Part identity stays `AY-3-8914-class, Intellivision register map` (D3, tier 4). A rule inventory `data/psg/rules.json` (ids `PSG-R01..`) gives each rule a statement, a `basis` in {`8910-primary-literal`, `8910-primary-derived`, `8914-community`, `default-unknown`}, source locators, the profile fields it reads, covering vector ids and a discrepancy id. A new gate step checks every rule has a field or engine marker, at least one vector and a source or an `unknown-default-chosen` tag with resolver and trigger. 8910-derived rules are tagged `inference`, so dependent claims stay provisional (C11, C12, C69).
- **D-08:** Register file: sixteen 16-bit bus words at `$01F0..$01FF`, only the low byte driven, layout, write masks and read masks exactly as the `psg.regmap` table in `05-DISCUSS-psg.md` P-2 (tier 4, C70; GI numbers registers in octal, ids carry both). Stores keep `value & wmask`; reads give `reg & rmask` with bits 15..8 zero; no side effects; no mirrors (`psg.mirrors = none`, `unknown-default-chosen`, C74); R10 read-back default follows the part-specific source with a one-field reversal (C75). The CPU sees a memory-mapped model (one logical access per READ/WRITE/DW; BDIR/BC1 are not state).
- **D-09:** Time chain: one PSG step = 8 PSG clocks = 16 master ticks = 4 CPU cycles (NTSC) (`psg.clocks_per_step = 8`, `inference`; `ticks_per_psg_clock = 2` retagged from `unknown-default-chosen` to `inference`; chip clock is crystal/2, C76). Tone half-period = P steps; noise shifts every 2*NP steps; envelope steps every 2*EP steps; counters are integers, no accumulator. This CORRECTS `docs/time-base.md` (which says a PSG step is 16 chip clocks); the correction lands before any PSG code. Samples per nominal frame are 3,733.5, so frames are never PSG-aligned.
- **D-10:** Tone: down-reload counter, a period write takes effect at the next reload (`psg.counter_model`, `unknown-default-chosen`). Period zero is three separate fields: tone 4096 (tier 4, C12), noise 32 (`unknown-default-chosen`), envelope 65536 (tier 4, C12). Noise: right-shifting Galois LFSR `{width: 17, galois_mask: "$12000", seed: "$00001", out_bit: 0, invert: 0}` (`unknown-default-chosen`, C71; the community mask `$14000` is a one-field edit and has a non-maximal period). Envelope: GI state machine for the 16 shapes with continue/attack/alternate/hold semantics, restart on shape write (C72). Mixer: enable polarity 0 = enabled, `chan = (tone | tone_dis) & (noise | noise_dis)`, port direction bits per D-04. Amplitude: 4-bit index (field width allows a wider profile), envelope-enable bit per channel. Reset: registers zero, tone outputs 0, LFSR = seed, envelope held at 0, both ports input.
- **D-11:** DAC levels are a profile field `psg.dac.levels` (`inference`, C12): 16 unsigned integers in units of 1e-8 of full scale from the GI Fig. 9 labels (levels 15..9 printed, 8..1 extrapolated and noted, 0 = 0). The core never reads it; hosts and `tools/pcm` do. A wrong table cannot invalidate raw audio goldens.
- **D-12:** Rules without a primary source (period 0, envelope select map, LFSR, DAC, port direction order, mirrors, R10 read-back, clock phase) appear as tier-tagged profile data with discrepancy entries C69..C76 as allocated in `05-DISCUSS-psg.md` section 5.3 (C11 and C12 updated, not reopened: C60, C64, C65, C66, C67). The next free id after C76 is C77; plan 05-01 owns ONE allocation table across all new entries (including the verification note's extra items) so no id is reused.

### Raw audio and the write log (AUD-02, API)

- **D-13:** Register-write log: one 16-byte record per guest write to `$01F0-$01FF`: `tick` u64 (master tick: unit start + access offset in CPU cycles * ticks per cycle + `psg.write_strobe_ticks`, default 0, `unknown-default-chosen`), `value` u16 (raw bus value), `addr` u8 (low nibble, Intellivision order), `source` u8 (1 = CPU write, 2 = interrupt-entry write; pinned by `data/expected/psg-log-source.ids`), `reserved` u32 = 0. No synthetic power-on records, reads are not logged (adding them is a domain-19 v2), ticks strictly increase.
- **D-14:** Log buffer: a third caller-owned buffer (`psg_log`, `psg_log_capacity`); required capacity from the Phase 4 frame-slot formula times a profile-published, property-tested bound `psg_log_records_per_frame` (`W_log = ceil(F/g) + ceil(U/g) + 1`); refused before any state change with new reasons `RUN_PSGLOG_NULL`, `RUN_PSGLOG_OVERLAP`, `RUN_PSGLOG_SMALL` appended to `api-reasons.ids` (stage joins the 4b/4c ladder after audio). A never-expected safety net stops with the existing `IVS_STOP_INTERNAL`. No new stop reason.
- **D-15:** Samples: one per chip step, stamped exactly `k * P` master ticks (P = 16, `psg.sample_period_ticks`, published in `ivs_info`), absolute grid from reset. Each sample is 4 bytes `level_A, level_B, level_C, 0` (post-mixer effective amplitude index per channel, format id `IVS_OUTPUT_FORMAT_PSG_LEVELS_V1`), per channel, not mixed, no DAC, no analog constant in the core. 223,721.5625 samples per emulated second. The PSG research note's packed `u16` form is NOT adopted (see Reconciliation).
- **D-16:** Generation is lazy and slicing invariant: `psg_catch_up(to_tick, sink)` and `psg_write(stamp, ...)` (catch up, apply, log). A sample at `k*P` observes writes stamped `< k*P` (step first, then write; `unknown-default-chosen`, resolver D10). At the end of every run call the PSG is caught up to `now` (the unit boundary), never to the target. The sink is a per-call stack struct; a NULL buffer runs the same code against a counting sink and never changes machine state (named fault `AUDIO_STATE_DEPENDS_ON_BUFFER`). The core retains O(1) state, never samples or records. A naive stepper stays as the reference if a fast path is ever added.
- **D-17:** Audio capacity uses the frame-slot formula with slack: `audio_bytes_per_frame = sample_bytes * (ceil(F/P) + s)`, `s = ceil(U/P) + 1`, where `U` is the proven maximum ticks of one CPU unit published as profile data and asserted by a property test over every opcode with maximal waits. Amends Phase 4 D-06: a capacity of 0 with a NULL buffer now means "channel not requested" (no check, no bytes, state unchanged); a nonzero capacity below the requirement is still refused before any state change. Note for Phase 6: adopt the same rule for video.
- **D-18:** Digests: domain 17 (AUDIO) becomes live, a chain over LEVEL-CHANGE records (index = change count, so it does not depend on call boundaries) plus `prev_levels` and `emitted` (a longer silent run changes it); domain 19 (new, `IVS_DIGEST_PSGLOG`) chains the 16-byte log records. Both are observation domains reported individually, cleared by reset, outside the composite. The runner recomputes the audio chain from the bytes it received (`audio.chain.check`). A slicing-invariance test of both chains is mandatory (the Phase 4 `index || len || record` per-call framing must not be reused for audio). PSG device state (counters, LFSR, envelope, previous levels, registers, `port_pulldown`) joins the instance state and the COMPOSITE digest by a deliberate composite version bump to v2, with the Phase 4 v1 composite literals pinned first and the golden change classified (only composite, instance and audio lines may differ).
- **D-19:** Public API: no new function. `ivs_run_request` v2 (appends `psg_log`, `psg_log_capacity`), `ivs_run_report` v2 (appends `audio_first_index`, `psg_log_bytes_written`, `psg_log_first_index`), `ivs_info` v3 (appends `audio_sample_ticks`, `audio_sample_bytes`, `psg_log_record_bytes`, `psg_log_records_per_frame`, `crystal_hz_num/den` passthrough the core never reads). Rewrite the minimum `struct_size` check to a pinned `IVS_RUN_REQUEST_V1_SIZE` (64) with the nonzero-tail rule rebased on the core's own size; v1-sized callers keep working. `data/api/api-effects.json`, `api-reasons.ids`, the digest-domain inventory and the installed consumer (one audio scenario printing `digest.audio` and `digest.psglog`, compared with the runner golden) are updated in the same plan.
- **D-20:** Runner: report format `ivsr 2` with new keys after `output.audio.bytes` (`output.audio.samples`, `output.audio.changes`, `output.psglog.records`, `output.psglog.bytes`, `digest.psglog`, `audio.sample_ticks`, `audio.chain.check`, `refpcm.*` only when `--audio-wav` is given); operator-only options `--audio-raw`, `--psg-log-out`, `--audio-wav` with `--wav-rate`, `--audio-out-max-bytes` (exclusive create, written only in `hostio.c`); IVSS gains `capture psglog|audio` (cap 4096, overflow is a harness failure) and `assert psglog ...`, `assert audio ...`, `assert digest audio=|psglog=`. No directive names a file or a rate. Exit codes and the outcome taxonomy are unchanged.
- **D-21 (D7, decided):** No PCM, resampling, filtering, DAC-table use or WAV code in `ivs_core` or any installed artifact. A pure integer reference converter (`tools/pcm/ivs_refpcm.h/.c`: no I/O, no allocation, no floats, no globals) is an internal static target linked only by the runner's `--audio-wav` and its own tests. Algorithm shape: sum of the three DAC levels, an exact rational box filter at 44,100 or 48,000 Hz, a one-pole DC block with caller-owned state, signed 16-bit mono. The symbol deny list gains `refpcm`, `resample`, `wav`, `pcm`; `pkg-install-files.ids` proves the install prefix has none. Its tests and `.refpcm` golden are tier `deterministic-repeatability`, labelled "reference conversion v1, converter repeatability only", and nothing in the digests, claims or `important-gates` for AUD-02 depends on it. Reversal: an adapter that must produce bit-identical PCM across hosts promotes it to an installed `ivs::refpcm` target, still outside the core.
- **D-22:** Human-listenable check without human UAT: an operator-only WAV from a local helper script with its sha256 recorded; the owner handoff is listening only. Everything else (pitch within 1% of `crystal/(32*TP)`, chain self-check, goldens) is automated.

## Amendments from research (override the matching text above)

Research (`05-RESEARCH.md`, executed against the code) found these CONTEXT assumptions false or incomplete. These amendments are binding and win over D-01..D-28 where they differ.

- **A-01 (D-13, D-16):** the bus context is `&im->mem`, which has neither the unit start tick nor ticks-per-cycle. A machine-level bus wrapper supplies them; the write-log stamp and the PSG catch-up go through it.
- **A-02 (D-16):** catching the PSG up only at the end of a run call is not enough. The seam-stepped twin instances (compared by `memcmp` with run-call instances) require the PSG to be caught up to the unit boundary at EVERY unit end, in the step seam and in run alike.
- **A-03 (D-14, D-17):** derived constants (executed over all 1024 decles, SDBD off and on, waits 0, 1 and 35): minimum gap between two PSG writes g = 9 CPU cycles = 36 ticks; maximum unit U = 48 ticks at wait 0 and 468 ticks with 35 waits on every wait-taking access. Publish U = 468 (`wait_limit_cpu_cycles` bound) and g = 36. The notes' illustrative g = 28, U = 608 are wrong for this code; recompute `W_log` and the audio slack `s` from these in the plan.
- **A-04 (D-19):** the pinned-V1-size treatment applies to the report (112 bytes, `*rep = r`) and the env seam as well as the request.
- **A-05 (D-23, V-05):** flipping `psg_regs` to `impl=real` in the memmap literal cannot happen in the oracle plan: the generator rejects it, the `memmap` suite needs a rule row and descriptor row, and the width probe needs the literal split by register width. The flip lands in the register-file plan. Likewise `data/golden/diag-ctrl-psg-1.expect` cannot be committed before its scenario and a dev report exist: plan 05-01 commits the derivation as documentation, the fixture plan commits the golden.
- **A-06:** a second table generator (`IvsPsgTable.cmake`) is needed for the `psg.*` object fields (register map and parameters), beside `IvsCtrlTable.cmake`.
- **A-07 (D-21):** `tools/pcm` sits outside four guards (runner-scan, the c-build unlisted-source guard, the integrity anchor, the fault modules). The plan must extend each deliberately. The symbol deny list only labels; the real guards are the install inventory and the public-symbol rule.
- **A-08 (D-25):** the 26-fault figure is a guideline and is already exceeded by `AUDIO_STATE_DEPENDS_ON_BUFFER`; the per-plan caps (5 tasks, 8 faults, 25 controls) stay binding.
- **A-09:** goldens are re-blessed in three or four behaviour plans (composite v2 foundation, audio live, noise/envelope, runner key list), each a classified diff.
- **A-10 (D-23):** `refs/` does not cache the 1980/1982 GI catalogs. Plan 05-01 fetches them, verifies hashes against the registry and keeps them gitignored. Network, `pdftotext`, `pdftoppm`, `tesseract`, `qpdf`, dash and docker (`ubuntu:24.04`) are available.

## Reconciliation (conflicts between the four notes)

- **Sample record:** the audio note (4 bytes, three level bytes plus reserved) wins over the PSG note's packed `u16` (three 4-bit nibbles). Reason: a profile with a wider amplitude (the 8914's 6-bit amplitude register is unverified, C70) fits without a format change; the semantic is the same post-mixer level index.
- **Step and clock:** the PSG and audio notes agree (8 PSG clocks = 16 master ticks); both contradict `docs/time-base.md`, which is wrong and is corrected first (D-09).
- **Audio digest framing:** the verification note warned that the Phase 4 per-record `index || len || record` framing could break slicing invariance. The audio note's chain is over level-change records indexed by change count with the emitted count bound in, which is call-independent; D-18 keeps it and makes the slicing test mandatory.
- **Composite digest:** the audio note left the composite to the orchestrator; the verification note recommends pinning the Phase 4 v1 literals, then bumping to v2. Decided: v2 (D-18), so guest-visible PSG state cannot differ undetected.
- **Report format:** the controller note adds no report keys (`ivsr 1` is closed); the audio note bumps to `ivsr 2` for audio keys. Compatible: the bump happens once for audio; derived controller bytes stay observable through peek and `assert mem`.
- **Discrepancy ids:** the PSG note allocates C69..C76; the verification note listed its own C69..C74 for overlapping topics. The PSG allocation wins for its topics; remaining items start at C77 under one allocation table in 05-01 (D-12).
- **Where PSG register state lives:** the controller note puts `port_pulldown` in `ivs_memsys` next to the register file; the PSG note puts device state under the machine layer. Decided: registers and `port_pulldown` in `ivs_memsys` (reads stay pure), counters, LFSR, envelope and sample phase in a PSG device struct owned by the machine, both inside the instance and the composite.
