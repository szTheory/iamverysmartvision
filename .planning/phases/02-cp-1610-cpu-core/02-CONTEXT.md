## Implementation Decisions

### Stepper shape and state (CPU-05)

- **D-01:** One `ivs_cp1610_step` executes exactly one *unit*: an instruction, interrupt entry, reset entry, bus-grant wait or halted idle. SDBD is its own unit that sets `dbd`; the next unit consumes it. No per-microcycle or pin-style tick core and no coroutine state, because Phase 1 evidence is boundary-only and mid-instruction state would leak into snapshots. Overshoot of a run target is at most one unit. Confidence ~75%. Reversal: hardware trace showing a STIC steal or interrupt landing mid-instruction, or a C19 resolution that needs mid-instruction acceptance. — **Reversibility:** costly — every vector and the later machine scheduler assume unit granularity, but the access-stream contract (D-02) lets a micro-stepped core replace it without an API change.
- **D-02:** Access reporting is one record type used two ways. `ivs_cp1610_access` is 12 bytes: `offset_cpu_cycles` (u32, BAR cycle relative to unit start), `addr` (u16), `data` (u16), `wait_cpu_cycles` (u16), `kind` (u8), `flags` (u8). Kinds: FETCH, READ, WRITE, INTAK, IAB (vector read), STROBE_TCI, STROBE_PCIT. Idle NACT cycles are not recorded: they are the gaps to `elapsed_cpu_cycles`. The data phase is `offset + 2` (documented inference).
  - A synchronous bus port `ivs_bus_reply (*ivs_bus_fn)(void *ctx, const ivs_cp1610_access *a)` is called for every non-idle record in order and returns `{data, wait_cpu_cycles}`. Reads use `data`, writes use only the wait. It must not re-enter the CPU. A read answer must be supplied during the step, because the fetch, effective-address, read chain is sequential and a later catch-up scheduler must advance devices to the access time first.
  - An optional caller-owned log (`log`, `log_cap`, NULL allowed) receives the same records. `log_cap` below `IVS_CP1610_MAX_ACCESSES` (8; real worst case ~4) refuses the step with `IVS_E_BAD_ARG` and leaves state untouched. The log is never truncated mid-step, so state never depends on log size.
- **D-03:** `ivs_cp1610` state is a plain 32-byte struct embedded by value: no pointers, `bool`, enums or bitfields; explicit padding; `_Static_assert(sizeof == 32)`. Fields: `uint16_t r[8]` (R6 = SP, R7 = PC); `uint8_t status` in the manual's GSWD layout (C=0x10, OV=0x20, Z=0x40, S=0x80); `intff`; `dbd`; `prev_interruptible`; `run_state` (RESET_PENDING, RUNNING, HALTED, FAULTED); `halt_pending`; `fault_reason`; `busak`; zeroed reserved bytes. `IVS_CP1610_STATE_VERSION 1`, `ivs_cp1610_state_size()` and `ivs_cp1610_state_validate()` (rejects bad enums and nonzero reserved or unused status bits). Phase 8 serializes per field, little-endian, never by memcpy. The CPU keeps no time and no tick counter. — **Reversibility:** costly — snapshot format (Phase 8) and every test fixture read the layout.
- **D-04:** Time crosses the API only as `*_cpu_cycles` relative to unit start (D2 naming rule). The CPU never sees `ticks_per_cpu_cycle` or Hz. The machine layer computes `tick = unit_start_tick + offset * ticks_per_cpu_cycle` with the 2^63 guard. The unit-swap named-fault control queued in `docs/time-base.md` lives in the machine layer (Phase 3/4), not here.
- **D-05:** Per-step input is a const `ivs_cp1610_lines {intr, intrm, busrq, stpst}`, sampled by the caller after its devices were advanced. Acceptance happens at the start of the next step using `prev_interruptible` from the previous unit (CPU-02) plus the line levels. Bus replies are the only other external input, so a step is deterministic given (state, lines, replies). Unmapped or open-bus data and wait-state meaning are Phase 3 semantics; Phase 2 tests use a flat 64K x u16 bus with zero waits.
- **D-06:** Layout and naming. Prefix `ivs_` / `ivs_cp1610_*` (never "intellivision"; hard stop). `core/src/cpu/cp1610.h` (internal, not installed), `cp1610.c`, `cp1610_decode.c`, `core/src/common/ivs_status.h`; `core/include/ivs/` stays empty until API-01..06, so no ABI commitment exists. Tests live in `tests/cpu/`. `ivs_status` is an `int`: 0 = OK, negative = caller refusal (`IVS_E_BAD_ARG`, `IVS_E_BAD_STATE`); a refused call never mutates state. Guest faults (D-14) are not refusals: the step succeeds and reports them in its result.
- **D-07:** UB hygiene. All 16-bit math goes through `uint32_t` temporaries with an explicit `& 0xFFFFu`; decode masks `word & 0x3FF`; SDBD uses the low 8 bits of each word. State holds no signed fields. No dynamic allocation anywhere in `core/`; internal asserts use `__builtin_trap()`, not `assert.h`.

### Control-flow policy (CPU-02, CPU-03, CPU-04)

Each policy id gets at least one vector and one named-fault control (D-18). Items marked [default-chosen] go into the discrepancy log as unknown-default-chosen entries (C36+) with a revisit trigger. Unmarked items are [OBS] from pdf 22, 24, 25, 27-37, 40, 43, 47, 51, 55-57.

- **D-08:** Interrupt acceptance and entry.
  - POL-INT-01: after an interruptible unit, sample the lines once. BUSRQ is tested before INTR. INTR is always honoured; INTRM only if INTFF is set. Pins are levels, not latched.
  - POL-INT-02: non-interruptible per manual: the 8 shifts, EIS, DIS, TCI, CLRC, SETC. SIN is interruptible (pdf 13). [default-chosen, C19] HLT, SDBD and the MVO family (MVO, MVO@, MVOI, PSHR) are non-interruptible. Vector lists are literal, not table-generated.
  - POL-INT-03: EIS, JE, JSRE set INTFF; DIS, JD, JSRD, MSYNC clear it; GSWD/RSWD ignore it. [default-chosen] acceptance does not clear INTFF, and JE takes effect before the boundary test. Profile field `cpu.interrupt_accept_clears_intff=false`; vectors for both values.
  - POL-INT-04: entry order is INTAK (addr = R6), write R7 at R6, R6 += 1 mod 2^16, IAB read loads all 16 bits into R7. Flags are not pushed. The first ISR instruction always runs (pdf 22). Entry is 9 cycles: INTAK@0, DW@2, DWS@3, IAB@5, first BAR@9 (C30, inference now corroborated by the printed timing figure).
  - POL-LINE-01: [default-chosen] the machine samples the lines once per interruptible boundary at unit end minus one CPU cycle (the final TS1). This is a machine-layer rule; the CPU only receives the sampled values (D-05). Revisit in Phase 6 (STIC races).
- **D-09:** Vector supply and reset.
  - POL-IAB-01: the core holds no vector constant. IAB is a bus access kind (reason = reset or interrupt) answered by the bus layer. Test providers return arbitrary 16-bit values. The Phase 3 machine bus answers reset with profile `reset.r7` ($1000) and interrupt with a new profile field `interrupt.iab_value` ($1004); both tier4-community, unknown-default-chosen under C32. Fault: the core hardcodes $1004. Confidence 85%.
  - POL-RST-01: reset models the MSYNC release. `ivs_cp1610_reset` zeroes registers and flags (profile zero-fill default), clears INTFF, DBD, stop and fault, sets RESET_PENDING; the first step is a reset-entry unit with IAB@1, first BAR@5 (5 cycles) that loads R7 from the bus. Other registers are untouched by IAB. Stepping before reset returns a `NOT_RESET` unit kind, never UB. Vectors: provider values $0000 and $FFFF.
- **D-10:** Bus grant and wait states.
  - POL-BUS-01: the grant happens only at an interruptible boundary, never after interrupt entry. BUSAK goes low at the unit end tick; the step reports a BUS_GRANTED unit with no accesses (idle cycles only). BUSRQ is re-sampled at each TS1; release latency is 2 cycles, held in a profile field [INF, ~60%, from the pdf 36 diagram]. The Phase 6 STIC drives BUSRQ as a function of tick.
  - POL-WAIT-01: each BAR/ADAR access takes `wait_cpu_cycles` from the bus reply, added as NACT cycles before the data transfer (pdf 40: BDRDY is sampled at TS1 after BAR/ADAR; pdf 43: "8+2W"). Default 0. Cap 35 (pdf 12: under 40 us); exceeding it faults with `BUS_WAIT_LIMIT`. Wait stamps cannot be precomputed; they come from replies.
- **D-11:** SDBD, stack, branches, undefined encodings.
  - POL-SDBD-01 (supported): modes 1-5 on the six indirect instructions and the six immediates. A DBD instruction costs 10 cycles plus the separate 4-cycle SDBD unit (C34 corroborated: indirect 4+10, immediate 14 total). Modes 4/5 do two reads and two increments. [default-chosen] modes 1-3 do one read and the register is not incremented (pdf 47 "only one word" vs pdf 57 "same byte twice" is a new discrepancy). Both bytes are the low 8 bits of their words.
  - POL-SDBD-02 (refuse): terminal fault `UNSUPPORTED_SDBD_TARGET` for modes 0 and 6 (direct, PULR, PSHR, @R6), MVO@, MVOI, branches, internal-reference instructions and another SDBD. Detected after opcode fetch; PC stays at the offender and DBD stays set; the fetch is traced and its cycles counted; no other effects. Refusal is monotone (a later documented behaviour never breaks a guest that used to run); treat-as-single is rejected because it hides bugs.
  - POL-SDBD-03: DBD is consumed by the next instruction. Interrupt and bus tests are skipped between SDBD and its target. Fault: SDBD interruptible (DBD leaks into the ISR).
  - POL-STK-01 (C17 resolved): R4/R5 post-increment on every indirect access; R6 post-increments on MVO@/PSHR and pre-decrements otherwise; all 16-bit wrapping; PC increments per word fetched and an R7 write overrides it.
  - POL-STK-02: [default-chosen] when DDD equals the pointer register (MVI@ R4,R4 or PULR R6), the result wins over the increment.
  - POL-MVO-01: MVO@ with SSS = MMM in 4..7 (patterns $264, $26D, $276, $27F, pdf 55) faults with `UNSUPPORTED_MVO_SSS_EQ_MMM`.
  - POL-BR-01: 7 cycles not taken, 9 taken; NOPP is the never-taken twin of B and always 7 (C29, ~80%); target is PC+2 plus displacement per pdf 47. BEXT calls an `ebci(E)` provider, [default-chosen] false.
  - POL-ILL-01: decode uses bits 9..0 only; bits 15..10 are ignored (property test over all 65536 words). NOP and SIN behave identically for both N values (the N bit is DDD bit 0; the pdf 51 footnote makes GSWD R4/R5 = NOP and R6/R7 = SIN). The three-way $2FF coincidence gives the same result. Jump DE=11 faults with `UNSUPPORTED_JUMP_DE`.
  - POL-HLT-01: [default-chosen, low confidence ~50%] HLT sets a stop latch evaluated at the next interruptible boundary, with priority over BUSRQ/INTR. The stopped state is terminal until resume or reset. This unifies pdf 14, 56 and the community "HLT non-interruptible" statement; it refines C35.
- **D-12:** Reporting and faults. Each step returns a result `{elapsed_cpu_cycles (u32), unit_kind (INSTR, INT_ENTRY, RESET_ENTRY, BUS_GRANT, HALTED, FAULT, NOT_RESET), n_accesses (u8), events (u8), opcode (u16), pc_before (u16)}`. Guest faults are sticky (`run_state = FAULTED`, `fault_reason`), cleared only by reset, and never abort. This supersedes the agent-1 idea of "succeed with an UNSUPPORTED event": the sticky fault is chosen because refusal is visible and monotone (D-11). Stamps are asserted exactly only for classes that have a printed timing figure (pdf 27-37); in-instruction offsets elsewhere are tagged `inference` and cycle totals stay authoritative. Pulse events (TCI, PCIT) may be stamped up to 1 cycle past the unit end. A fuzz-style run over random state, lines and opcodes under ASan/UBSan, and a guard that no-progress statuses never loop a `run`, are required.
- **D-13:** Discrepancy-log and notes work for the planner. Add entries for: intra-instruction access schedule is not tabulated; SDBD modes 1-3 one word vs same byte twice (pdf 47 vs 57); sampling-point and strobe-stamp inferences; HLT/C35 refinement; INTFF-not-cleared-on-accept; vector-value provenance (C32); residual shared-misreading risk of hand-derived vectors (D-16). Update the reference notes for the N bit (NOP/SIN), C34 (corroborated), C29 (NOPP twin) and the new timing figures (pdf 27-34, 36, 37, 40, 43). Add profile fields `interrupt.iab_value`, `cpu.interrupt_accept_clears_intff`, bus release latency, wait cap and EBCI default to `data/expected/profile-fields.ids` and the profile record.

### Vectors, inventory and fault controls (CPU-01, RUN-03)

- **D-14:** Authoritative vectors are JSON, one file per behaviour group (~10 files) under `data/cp1610/vectors/*.json`, each file's ids set-equal to a checked-in list, consistent with Phase 1 D-06. Per vector: `id` (`cpu.<ROW>.<slug>`), `row` (a row id), `kind` (`source` or `policy`), `tier` (`source-expectation`, only for kind=source), `cite` (`§x.y, pdf N`), `sources` (`["SRC-gi-cp1600-um-1975"]`), advisory `asm`, `program` (literal decles as hex plus a field-grouped binary string), non-empty `derivation` (paraphrase plus arithmetic), `init` (pc, R0-R7, flags, I, D, lines, memory as `[addr, word]` pairs), `expect` as a delta only, optional ordered `bus` `[cycle, kind, addr, data]`, `covers` tags. Harness rules: everything not listed in `expect` must be unchanged; memory outside the program is poison-filled and a read of an uninitialised address fails the vector.
  - The C harness consumes vectors without a JSON dependency: a `cmake -P` generator reads each vector (extract each into a sub-string first; measured 0.79 s vs 8.1 s for naive per-field access on 400 vectors) and emits an uncommitted C initializer table into the build directory via `add_custom_command` with DEPENDS on the JSON, embedding each source file's sha256. A hand-written C JSON parser is rejected (a second parser) and a committed generated header is rejected (adds a staleness failure class). Fallback if authoring JSON proves unbearable: the same data as JSON Lines.
  - Checker mechanics: the first decle must match the declared row's pattern (a label check, not a value source); `cite` matches the pdf-page regex; `sources` exist in `sources.json` (anything else fails closed); vector files carry no emulator names; policy vectors use `kind=policy` with a policy id, no tier, are counted separately and never support hardware claims.
- **D-15:** Independence. Expected values come only from the page: encodings from the format figures, results by hand arithmetic recorded in `derivation`, cycles from the summary tables. Emulator output is never pasted in. Disagreement rule: re-read the page and record the resolution; never edit `expect` to match output. A blind second reader extends Phase 1's `second-reader.json`: a small `cmake -P` script writes a blinded copy (init and program only) to scratch, a separate agent re-derives `expect` from the page images, a mechanical diff follows, and the marker records `file_sha256` plus disagreements and resolutions. Editing a vector makes the marker stale and fails the gate. Claims say "source-expectation, second-read", never `independent-implementation-comparison` (same model, same page: shared misreading is possible; the residual risk is logged and is closed later by Phase 4 original diagnostics and D10 hardware). libasm and similar sources are local leads only; nothing is committed from them without a manifest recording its licence.
- **D-16:** Coverage is behaviour-class based. The checker derives requirements from the table columns (the table stays an inventory only, D-20 of Phase 1): at least one vector per row (including the overlapping rows XORR/CLRR and MOVR/TSTR/JR); for each flag in `status_bits` a set and a clear case; for each flag not in `status_bits` a preserved case with the opposite initial value; one vector per `cycle_modifier` branch; one per addressing class (direct; indirect R1-R3; R4/R5 auto-increment; R6 pre-decrement/post-increment; immediate; SDBD forms; R6/R7 cycle bonus; R7 as destination). Edge operands {0000, 0001, 7FFF, 8000, FFFF}, at most ~5 vectors per row beyond the class cases; shifts N=0/N=1; the 16 branch conditions taken and not-taken, forward and backward; BEXT codes; J/JSR with BB=0..2 and DE; reset, interrupt and BUSRQ cases. Tags are cross-checked against each vector's own `expect` so they cannot merely be claimed. Expect ~300-360 vectors. A 1024-decle decode sweep checks words, PC advance, base cycles for rows without modifiers and that flags outside `status_bits` are unchanged; a mismatch against hand vectors is a discrepancy, never an auto-fix. Vectors whose cycle count is not yet read from the page (branch-taken cycles, the SDBD 10-vs-14 split where still unread) are expected-skips linked to a discrepancy id and counted.
- **D-17:** Exact inventory. Checked-in lists: `data/expected/cp1610-vectors.ids`, `data/expected/tests/<suite>.ids` (supersedes Phase 1's mention of `tests/expected-tests.txt`; existing `#`-comment, first-token format, with a `skip-ok` marker for permitted skips), `data/expected/cp1610-skips.ids` (id plus discrepancy). The harness prints TAP-like lines (`ok N name`, `not ok N name`, `ok N name # SKIP reason`), a header `# suite=<s> nonce=<n>`, a `1..N` plan and a trailer `# suite=<s> executed= skipped= failed=`, and writes `$IVS_TEST_OUT_DIR/<suite>.txt`; exit 1 on failure and 77 only for an all-skipped suite (ctest `SKIP_RETURN_CODE 77`, never for partial groups). The gate parses the TAP files, not ctest. ctest registers one test per suite with no conditional registration, and `ctest -N` is also compared against the suite list. Stale output: the gate creates `build/gate/NONCE` from `basename "$GATE_TMP"`, deletes `build/gate` before each run and the harness echoes the nonce. Duplicate execution is detected with a per-id bitmap. Failure output shows id, cite, derivation, a field diff and a bus-sequence diff; `--only <prefix>` and `--list` exist. Checker tokens: `tests-missing`, `tests-duplicate`, `tests-unlisted`, `tests-unexpected-skip`, `tests-stale`, `tests-truncated`, `tests-plan-mismatch`, `tests-failed`, `tests-suite-missing`, `tests-inventory-empty`, plus a vectors-digest mismatch and a stale second-reader marker. About 10-12 `tests-inventory-*` controls (missing, extra, duplicate, unlisted skip, stale review, stale digest, bad cite, row mismatch, ctest list drift) satisfy success criterion 1 using text overlays on `_good/tree`, with no runner change. Implement the checker with sh, awk and `comm`.
- **D-18:** Named-fault controls use compile-time `#ifdef IVS_FAULT_<ID>` sites of at most 3 lines each; a normal build never defines them (no production hook, no hot-loop cost). `tests/faults.cmake` defines `ivs_add_fault(ID ... SOURCE ... SUITE ...)`, which recompiles only the owning TU into a fault copy linked into a fault executable in the dev tree (EXCLUDE_FROM_ALL, not registered in ctest). `data/expected/faults/cpu.ids` holds `<id> <must-fail-vector> <allowed-prefix>` and the registry data carries `must_pass` sensitivity vectors. The checker requires: the fault binary's vector list equals the clean inventory; the `must_fail` vector fails; every failure starts with the allowed prefix; sensitivity vectors still pass; a baseline run with no fault passes. Tokens: `fault-not-detected`, `fault-wrong-reason`, `fault-collateral`, `fault-missing`. A set-equality check compares `IVS_FAULT_*` sites in `src/` with the expected ids (catches an orphan hook or an unexercised control). One extra control mutates a single `expect` in the JSON to prove the generator-to-harness path carries expectations. About 30 faults, one per behaviour class, covering at least: push/pull direction; R4/R5/R1-R3 auto-increment; SDBD indirect increment, immediate PC advance and flag-not-cleared; previous-instruction interruptibility, I flag ignored, BUSRQ priority, D/SDBD interrupted; reset entry; SUB/CMP carry, ADD OV, ADCR, INCR touching C; R6/R7 cycle bonus; shift N=1 cycles; MOVR to R7; JSR return address; bus order; plus every POL-* fault listed in D-08..D-11. Sufficiency rule: a plausible bug with no catching vector means add a vector. Rejected: a build dir per fault (0.5 s configure each), anchored source patching (anchor drift), and a runtime `--fault` switch in production code. Measured on a probe: 40 faults ~1 s compile (one TU each), 0.1 s to run. — **Reversibility:** reversible — hook style can swap to anchored mutants if hook clutter or leakage is found in review.

### Build, harness, purity, gate and CI (PKG-02, API-05, RUN-03)

- **D-19:** CMake skeleton. Root `CMakeLists.txt`, `CMakePresets.json` (v6; hidden `base`, then `dev` and `release` with matching build and test presets, binaryDir `${sourceDir}/build/${presetName}`, test presets set `execution.noTestsAction=error`), `cmake/IvsWarnings.cmake`, `include/` (empty for now), `core/` (D-06), `tests/{CMakeLists.txt,faults.cmake,harness/ivs_test.{h,c},cpu/*.c}`. Explicit source lists, no `file(GLOB)`; one OBJECT library per core source plus a STATIC `ivs_core`; C17, extensions off, hidden visibility, `-ffp-contract=off`. Warnings: `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Wsign-conversion -Wstrict-prototypes -Wmissing-prototypes -Wvla -Wundef -Wcast-qual -Wimplicit-fallthrough -Wdouble-promotion -Werror=date-time`; clang adds `-Wmissing-variable-declarations`; GNU adds `-Wlogical-op -Wduplicated-cond`. `-Werror` sits behind option `IVS_WERROR` (ON in presets, OFF by default, so a newer downstream compiler cannot break a consumer build). Other options: `IVS_SAN`, `IVS_FAULT_CONTROLS`. Presets: `dev` is Debug `-O1 -g` with `-fsanitize=address,undefined -fno-sanitize-recover=all` and fault controls ON; `release` is `-O2 -DNDEBUG` with no sanitizers and Werror ON. Both run in the gate (release catches `-O2`-only warnings, assert-side-effect bugs and optimizer-exposed UB; UB in 16-bit arithmetic is the D-01 flip condition). Do not set `detect_leaks=1` (fatal on macOS arm64). No MSan/TSan/fuzzing in the gate (Apple clang has no libFuzzer runtime; verified locally). Developer inner loop: `cmake --preset dev && cmake --build --preset dev && ctest --preset dev`. Set INTERPROCEDURAL_OPTIMIZATION off on the core target. Test the declared CMake 3.25 floor only if a consumer needs it (the floor is declared but untested).
- **D-20:** Harness is in-repo, `tests/harness/ivs_test.{h,c}` (~120 lines), explicit case table (no constructors, MSVC-safe), with the TAP-like output from D-17. No third-party test library (copy-paste over dependency).
- **D-21:** Purity (API-05) is enforced by an allowlist, not a denylist, in two layers; the symbol layer is authoritative.
  - Symbol layer: `tools/check/core-symbols.sh [--allow-prefix P]... FILE...` (reads `NM` from the environment, default `nm`) runs `nm -P -u` and `nm -P -g -U`, normalizes names (strip `@ver`; strip one leading underscore on Darwin), computes undefined minus defined minus allowlist minus prefixes, and fails closed with `-- FAIL core-symbols-forbidden: <sym>`. It also rejects: no input, a missing file, an nm failure, LTO objects (`.gnu.lto_`; token `core-symbols-lto`), bitcode (`BC\xC0\xDE` magic or wrapper, also inside archives; `core-symbols-bitcode`) and an input with zero external definitions (`core-symbols-no-definitions`; count external definitions with `-g`, since Apple clang emits a local `ltmp0` even for an empty object). Run it on one `ar` archive per variant (looping per object cost 390 ms for 8 objects against ~80 ms for one archive). Pass line: `-- core-symbols pass external=N defined=M`.
  - Allowlist `tools/check/core-symbols-allow.txt`, read from `CHECK_DIR` so controls cannot replace it: `memcpy`, `memmove`, `memset`, `memcmp`, `__memcpy_chk`, `__memmove_chk`, `__memset_chk`, `__stack_chk_fail`, `__stack_chk_guard`, `bzero` (Darwin). No assert, abort, malloc, libm or `__divti3`; add per-target entries when needed, each reviewed. An optional `core-symbols-deny.txt` (~40 known-bad names) only labels the failure category (`clock|fs|env|thread|io|rand|alloc`) and fails if the allowlist contains any of them. Sanitizer and coverage presets pass `--allow-prefix` for their runtime symbols (`__asan_`, `__ubsan_`, `__sanitizer_`, `__llvm_profile`, `__gcov_`, `section$`), set by the build option, never hard-coded. The shipped-release objects get the strict check; instrumented builds get the prefixes.
