## Stepper guest-input review (`core/src/cpu/cp1610.c`, `cp1610_decode.c`)

- **No unbounded loop.** The stepper has no loop over guest data. The only loops are the decode scan over the 74-row static table (`cp1610_decode.c:136`) and the 8-byte reserved check in validate (`cp1610.c:169`). Every unit is straight-line code.
- **Register indexing is always masked.** `r[reg & 7u]` (`ivs_wreg`, `cp1610.c:295`), `sss`/`ddd` extracted with `& 7u` (`cp1610.c:750-751`), shift and GSWD registers `& 3u` (`652`, `780`), jump save register `4u + bb` only for `bb` in 0..2 (`630-632`), indirect `mmm` from a 3-bit field (`940`, `1000`).
- **Access log is bounded.** `ivs_access` traps before writing if the per-unit count reaches `IVS_CP1610_MAX_ACCESSES` = 8 (`cp1610.c:133-138`); the deepest unit makes 3 accesses (fetch plus two operand words, or INTAK/DW/IAB). `ivs_cp1610_step` refuses a non-NULL `log` with `log_cap < 8` (`1313-1315`), tested by `cpu-api.refuse-small-log` (`tests/cpu/cpu_api.c:307-328`).
- **No signed or narrowing UB.** All arithmetic is done in `uint32_t` temporaries and stored through `IVS_U16` (`cp1610.h:23`); shifts are by constants 1..15 on values below 2^17; wait accumulation is `uint32_t` (at most 8 x 65535) (`cp1610.c:121-132`). The dev preset compiles core and tests with `-fsanitize=address,undefined -fno-sanitize-recover=all` (`cmake/IvsWarnings.cmake:26-30`, `CMakePresets.json` `dev`).
- **Hostile bus waits are capped.** A wait above the configured limit (a `uint8_t`, at most 255) sets a sticky `BUS_WAIT_LIMIT` fault, the unit length is `offset + 1 + limit + 1` regardless of the reply (`cp1610.c:127-130`), and the architectural state is rolled back (`1353-1358`).
- **Every decle decodes.** Decode masks the word to bits 9..0 (`cp1610_decode.c:134`) and the table is total over 1024 decles (`_Static_assert` of 74 rows at line 130; gate `patterns=1024 unclaimed=0 ambiguous=0`); `cpu-sweep.high-bits-65536` steps all 65536 words (`tests/cpu/cpu_sweep.c:276`) under ASan/UBSan.
- **Invalid caller input is refused without side effects.** NULL arguments, lines not 0/1, config with nonzero `reserved`, a non-bit INTFF flag or zero release latency (`1291-1301`, `1310-1320`), and corrupt state bytes (`ivs_cp1610_state_validate`, `153-175`) return an error before any write; the step works on a local copy and commits only at the end (`1324`, `1360-1361`).
- **No-progress cannot spin.** Steps that start in UNRESET or FAULTED take 0 cycles and change nothing (D-12); HALTED and BUS_GRANT units take at least 1 cycle and a zero release latency is refused (`1298-1301`). Checked on every step of 8 x 20000 seeded fuzz steps (`tests/cpu/cpu_fuzz.c:208-236`).
