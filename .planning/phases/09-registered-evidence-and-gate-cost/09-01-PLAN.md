Token discipline (the rule every plan in this phase states the same way):

- **Absolute-and-frozen**: `steps`, `controls`, `faults`, `fault-runs`, `gates`, `lines`, `cases`, `tests-expected`, `tests-executed`, `tests-skipped`, `tests-missing`, `claims`, `provisional`, `docs`, and the per-step stats a plan names (`goldens`, `reports`, `host-dependent`, `release-only`, `manifests`, `effective-yes`, `literal-rows`, `views`, `dump-lines`). Each is derived from committed inventory content this phase controls, so a plan predicts it exactly and an unexpected value is a stop.
- **Derived-at-run-time, never a predicate**: `files`, `tracked`, `hygiene-files` (every committed planning artifact under `.planning/` is tracked, so each one moves the count by one), `history-commits`, `ci-runs` (the orchestrator appends hosted rows), and the four measurement line shapes `step-time`, `gate-cpu`, `gate-time`, `gate-env`.
- **The delta form**: the baseline is the tree's file count at the start of the task, `git ls-tree -r --name-only HEAD^ | wc -l`; the gate prints the current count as `files=`, and `tracked=` and `hygiene-files=` are the same count measured twice more. A prediction is `files - <that baseline> == <the exact number of files this task adds>`, with `files == tracked == hygiene-files`. Because the baseline is derived at run time it cannot go stale; the absolute value is a recorded observation in the SUMMARY, never a verify predicate.
- **Where a stop belongs**: on the absolute-and-frozen tokens this plan names and on the deltas it predicts. It does not belong on `files=`/`tracked=`/`hygiene-files=`/`ci-runs=`/timing compared against any earlier log — those move for reasons this plan does not control, which is exactly why they are asserted as deltas.
