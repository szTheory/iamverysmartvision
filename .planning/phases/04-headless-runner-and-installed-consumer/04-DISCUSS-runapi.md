## 1. Facts that constrain the design [OBS]

- D2 is one-way: machine time is a `uint64_t` master tick; "core run contract is `run(target_tick)` returning `now_tick`, `overshoot_ticks` and a stop reason; a target above 2^63 is refused with an explicit stop reason"; "a CPU-cycle convenience helper lives in the runner, not in the core API". REQUIREMENTS says "absolute cycle target" in words, but the glossary bans the bare unit word for a master tick, so the API unit is the master tick and the CPU-cycle form is runner sugar.
- The only stepping primitive is `ivs_machine_step_unit_internal`: one CPU unit; `time_ticks += elapsed_cpu_cycles * ticks_per_cpu_cycle` (4). Lines are all inactive (no device drives INTR/BUSRQ/STPST). Overshoot is at most one unit (Phase 2 D-01).
- CPU units that make no progress: `UNIT_FAULT` after a sticky fault returns `elapsed_cpu_cycles = 0` forever (default branch of `ivs_cp1610_step`); `UNIT_NOT_RESET` is 0 but unreachable once POWERED. `HALTED` idles 1 CPU cycle per unit (4 ticks) with no wake source until a Phase 5/6 line exists. Phase 2 D-12 already demands "a guard that no-progress statuses never loop a run". A run loop must therefore classify, not just count.
- `ivs_cp1610_step` can return non-OK mid-run (invalid state or config). A run that has already committed units cannot then claim "refused, effect none". Validate first; treat a mid-run non-OK as an invariant violation with its own stop reason.
- Public conventions to reuse: `struct_size` first (in: short is BAD_ARG, above `IVS_STRUCT_SIZE_MAX` BAD_ARG, larger accepted only if the tail is zero else UNSUPPORTED; out: short is BAD_ARG, write min), nonzero flags UNSUPPORTED, out params must not overlap instance storage (checked after BAD_HANDLE), refusal writes only detail fields (reason table is append-only, 1..33 used), validate-then-commit (D-10), every refusal effect `none` proven by whole-storage memcmp plus digest equality, one-line `IVS_API` prototypes (the effects checker parses them), every pinned non-OK status must be cited by some refusal row (`api-dead-status`).
- Digest framing: per-domain preimage `"IVSD" || u8 domain || u16 version || rows`, composite `"IVSSTATE" || u16 version || (u8 domain || sha256)` for domains 1..4; ids 16/17/18 are reserved and refused today. One field table covers every instance byte exactly once (coverage test). Instance size is a `_Static_assert` (113,456).
- Output formats are not decided: STIC geometry is D8 (Phase 6), PCM location is D7 (Phase 5/7), controller form is D6 (open). `time-base.md`: a frame is a timeline event, never a modulo.

## 2. Lenses (condensed)

- Emulator architect: a run is `while now < T: step`. For slicing invariance the loop condition is the only place T may appear; T must never reach a unit, a device catch-up or a buffer flush. Devices catch up to the CPU position (`now`), never to T. This is the bug class of catch-up schedulers [INF]: a sync point that depends on the slice changes results, so the slicing test is the permanent guard for Phase 6/7.
- Hardware/EE: nothing in the machine knows "a run"; the only hardware-meaningful time is the boundary sequence b0 < b1 < ... of whole units. Controller lines are electrical (active-low port bytes, BSR and wiki consistent [INF from research notes]); a logical button mask loses the ambiguous combinations (INP-02).
- QA: one oracle problem. Digests prove repeatability only (`deterministic-repeatability`); only a guest-state predicate derived outside the emulator can back `original-diagnostic`. A digest of an empty domain must never look like a match that means something (vacuous green).
- Security/rights: a run takes caller memory (events, buffers). Everything caller-supplied is validated before the first write; no pointer is kept; the loop is bounded by the caller's target and by event count; no host clock. Goldens contain digests and predicates only, never ROM bytes.
- DevOps/CI: runtime cost must be small (hosted budget 40 s, trigger 50 s). Slicing tests use a tiny stand-in program and CPU-domain digests per unit, full composite only at slice ends. No new CI check; the tests ride the existing `tests-inventory` with exact ids.
- API/integrator: three-argument call with one versioned request struct; a host can single-step with `run(now+1)`; hosts that need frame pacing use a later `STOP_AT_FRAME` flag; no callbacks, no allocator, no globals (D-07 `nm` check).
- Product: Phase 4 must not claim video or audio. Reports say `video: none`, `audio: none` explicitly.
- DX: one idiom for every slice, replay and test: absolute targets are idempotent (calling again with the same or an earlier target is a harmless no-op, so a retry or a cancelled loop cannot double-run).

## 3. Options considered

### 3.1 Run contract
1. [REC] Absolute target in master ticks; run to the first unit boundary at or past it; report `now`, `overshoot = max(now - T, 0)`; stateless between calls. Pros: D2-faithful; idempotent; slicing-invariant by construction; nothing to save in a snapshot. Cons: overshoot up to one unit (at most `35`-wait-limit-class bounded, a few tens of ticks) [INF].
2. Relative budget with carried deficit ("run N, owe M"). Common in frame-driven cores. Footgun: the deficit is hidden state that must be in every digest and snapshot; Phase 8 save state would have to carry it. Rejected.
3. Stop before the unit that would pass the target (undershoot). Needs the next unit's cost before running it (execute then rollback); a host cannot guarantee `now >= T` (frame completeness). Rejected; kept as a named-fault control (`RUN_STOP_BEFORE_OVERSHOOT`).
4. Run-to-event only (`run_frame`). Hides time and cannot express API-02. Frame as an optional stop flag only (section 4.9).

### 3.2 Empty video and audio before Phase 6/7
1. [REC] Zero-length domains in the shipped profile: layout says format NONE, sizes 0, digest domains exist with "no producer" semantics; the API-04 rule is real code, tested at a seam with a synthetic layout. Pros: no fabricated evidence, no format lock-in (D7, D8 stay open). Cons: the refusal path is not reachable through the real profile until Phase 6/7 (mitigated by the seam, same precedent as `ivs_machine_cart_span_check`).
2. Placeholder frame (for example 160x96 zeros) and a placeholder audio block. Pros: refusal reachable now. Cons: invents an ABI-visible size that D8 will change; zeros would be hashed and could be mistaken for a rendered black frame; rejected.
3. Instance-internal ring buffers read later with a `read_output` call (Blargg-style `end_frame` then `read_samples`). Pros: no undersized-refusal problem. Cons: new instance state (large), a second call to sequence, and a buffer bound still needed. Rejected for now; revisit at Phase 7 if run-time back-pressure (`STOP_OUTPUT_FULL`) proves awkward.

### 3.3 Input schedule
1. [REC] Core-owned schedule semantics, caller-owned storage: the request carries a sorted array of `{tick, channel, value}`; the core applies every event with `tick <= now` at each unit boundary (and once more at exit), returns `events_consumed`, keeps no pointer. One canonical quantization rule for every host.
2. Host sets input between runs (`ivs_machine_set_input`). Simpler core but each host re-invents "apply at which boundary"; slicing equivalence then depends on host discipline. Rejected as the primary path (a trivial `set_input` can exist later if a host wants it).
3. Callback polled by the core. Violates D-03/D-07. Rejected.

### 3.4 Digest accumulation for video, audio, input
1. [REC] Per-domain running chain in instance state (`chain[32]`, `count u64`), updated per record: `chain' = SHA256("IVSR" || domain || chain || u64 index || u32 len || record)`. Pros: constant size, resumable, independent of host buffer capacity and slicing; fits the one-field-table coverage rule. Record granularity (frame, audio block, input event) is defined by the phase that produces records.
2. Streaming SHA context over the whole stream. Elegant, but its internal buffer bytes become digest rows; more state, harder to audit. Rejected.
3. Hash the caller's buffers at the end of each call. Depends on slicing and buffer size; rejected (it would break API-02).

## 4. Recommendation (sub-decisions, each concrete enough for a CONTEXT D-xx)

1. Signature (one line, `IVS_API`): `ivs_status ivs_machine_run(ivs_machine *m, const ivs_run_request *req, ivs_run_report *rep);` One call, absolute master-tick target, no relative form, no max-units, no callbacks. A single step idiom is `run(now + 1)` (always exactly one unit). `ivs_machine_step_unit_internal` stays internal and is the only stepping primitive.
2. `ivs_run_request` (in; `struct_size` first; flags and tail rules of D-04): `uint32 struct_size; uint32 flags; uint64 target_ticks; const ivs_input_event *events; uint32 event_count; uint32 reserved(0); uint8_t *video; uint64 video_capacity_bytes; uint8_t *audio; uint64 audio_capacity_bytes;`. Constants: `IVS_RUN_TARGET_MAX 0x8000000000000000` (2^63; a target equal to it is accepted, above it refused), `IVS_RUN_EVENTS_MAX 65536`, `IVS_RUN_F_STOP_ON_HALT 0x1` (0x2 reserved in a comment for `STOP_AT_FRAME`, UNSUPPORTED until Phase 6). `ivs_input_event` is a fixed 16-byte element: `uint64 tick_ticks; uint32 channel; uint32 value;` (extension is by new channel ids, not by growing the element).
3. `ivs_run_report` (out; written min(size, own) after validation; on a refusal only `refusal_reason` and `struct_size` are written, and nothing if the report itself is the cause): `struct_size; stop_reason; refusal_reason (IVS_REASON_*, append 34..); cpu_run_state; cpu_fault_reason; events_consumed; uint64 now_ticks; overshoot_ticks; elapsed_ticks (now minus entry now); units_executed; video_frames_completed; video_bytes_written; audio_bytes_written;` The last three are 0 in Phase 4 and exist so the API-04 tests can assert exact write extents later. `video_frames_completed` counts events, never derived by modulo.
4. Stop reasons (append-only, pinned in a new `data/expected/api-stop-reasons.ids`, checked like statuses): `NONE 0` (refusal, nothing ran), `TARGET 1`, `CPU_HALTED 2`, `GUEST_FAULT 3`, `INTERNAL 4` (a unit step was refused or made no progress: an invariant violation, a harness failure, state is the last whole boundary). Reserved in a comment, not defined: `FRAME 5`, `OUTPUT_FULL 6`. The reason is a pure function of exit state: `GUEST_FAULT` if the CPU is FAULTED, else `CPU_HALTED` if the flag is set and the CPU is HALTED, else `TARGET`. Priority guest condition over target, so a fault that coincides with the bound is never reported as a clean finish. A guest fault is `IVS_OK` plus a stop reason, never a status (status header: guest faults are not refusals). Add `IVS_API const char *ivs_run_stop_name(uint32_t reason);` ("IVS_STOP_TARGET", ..., "IVS_STOP_UNKNOWN") so no host keeps its own table.
5. Semantics, exactly: entry validation (section 4.6); then `loop { apply events with tick <= now; if exit_condition(state, flags, target) break; step one unit; if step refused or elapsed == 0 and not a fault: stop INTERNAL }`. `exit_condition` = FAULTED, or flag and HALTED, or `now >= target`. Consequences: target <= now is a no-op with `units_executed 0`, `overshoot = now - target`; a FAULTED CPU is never stepped; HALTED without the flag idles 1-CPU-cycle units to the target (no fast-forward in Phase 4; a later skip must land on the same 4-tick grid, `now + 4*ceil((T-now)/4)`, to preserve invariance, and the slicing test must cover it); `now + unit` cannot overflow because T <= 2^63 and a unit is at most tens of ticks.
6. Validation order (first failing class wins; every refusal effect `none`; no state read after the first commit can fail): (a) BAD_ARG: req NULL or `struct_size` short or above 4096; rep NULL or short (nothing written); (b) BAD_HANDLE; (c) BAD_ARG: rep overlaps instance (nothing written, after the handle check per WR-01); (d) UNSUPPORTED: unknown flag bits, nonzero tail bytes; (e) BAD_ARG with reason: events NULL with count > 0, count above `IVS_RUN_EVENTS_MAX`, video/audio NULL with capacity > 0, any of events/video/audio overlapping the instance or video overlapping audio (tested only on spans that passed the bound checks, A-08 a: a refusal never depends on where the host put a buffer except the overlap rule itself); (f) BAD_STATE: phase OFF; (g) OUT_OF_RANGE: target above 2^63 (this is the "explicit stop reason" of D2, implemented as status plus reason `RUN_TARGET_RANGE`, with `docs/time-base.md` amended by one line); (h) BUFFER_TOO_SMALL: `video_capacity < layout.video_min` or `audio_capacity < layout.audio_min`, before any step, event or write (API-04); (i) BAD_ARG with reason: events not sorted by tick (equal ticks allowed, array order kept), or a channel the profile does not register (A-08 e: unknown enumerant is BAD_ARG), found by scanning the whole array before anything commits; (j) the CPU state and config are validated once (damaged is BAD_HANDLE, same class as a damaged profile index). No new status number is needed: `BAD_ARG, BAD_HANDLE, UNSUPPORTED, BAD_STATE, OUT_OF_RANGE, BUFFER_TOO_SMALL` are all pinned.
7. Output layout lives in `ivs_info` by appending (struct_size rule makes this the intended use): `video_format, video_width, video_height, video_frame_bytes, video_min_capacity_bytes, audio_format, audio_unit_bytes, audio_min_capacity_bytes`, plus the timebase a host adapter needs: `ticks_per_cpu_cycle, ticks_per_stic_clock, ticks_per_psg_clock, nominal_frame_ticks (profile figure, documented "nominal, not a frame event"), crystal_hz_num, crystal_hz_den`, plus `cpu_run_state, cpu_fault_reason`. Phase 4 values: formats `NONE (0)`, every size 0. The rule for later phases is fixed now: video min capacity is one full frame; audio min capacity is the largest byte count one unit can produce; `OUTPUT_FULL` (reserved) stops a run at a boundary when the next unit might not fit, which keeps buffer size out of the machine state.
8. Test seam for API-04 (precedent `ivs_machine_cart_span_check`): the public call is a thin wrapper over `ivs_machine_run_env_internal(m, req, rep, const ivs_run_env *env)` declared only in `machine/machine.h`; `env` carries the output layout and the input channel table (the wrapper passes the profile's, which is empty in Phase 4). Tests pass a synthetic env (video min 64, audio min 16, channels 0 and 1) to prove: undersized capacity gives `BUFFER_TOO_SMALL` with whole-storage memcmp equal, exact size is accepted, NULL-with-capacity, overlap, ordering and consumption. The wrapper adds no logic, so the env is the only difference between the public and the tested path.
9. Frame target is a derived convenience, in the runner only: scenario bound `frames N` becomes `now + N * nominal_frame_ticks` and the runner prints the converted tick target next to a banner "nominal frames, not frame events". True frame stops arrive as `IVS_RUN_F_STOP_AT_FRAME` in Phase 6 when a frame event exists. CPU-cycle bounds (`cpu_cycles N`) are the same kind of sugar (`N * ticks_per_cpu_cycle` from `ivs_info`).
10. Cancellation and wall-clock timeout live in the runner: it loops `run(min(now + SLICE_TICKS, bound))`, checks its flag and clock between slices, and owns outcome mapping. This is the practical use of slicing invariance, and the slice size is a runner constant recorded in the report (default 59,736 ticks, one nominal frame length; any value gives the same digests).
11. Input log domain without Phase 5: the schedule mechanism (4.2 and 4.5) and the input chain are implemented and tested through the synthetic env; in the real profile no channel is registered, so a nonempty schedule is `BAD_ARG` (reason `RUN_EVENT_CHANNEL`) and the input domain digest is the digest of the empty log. Record bytes for the chain: `u64 applied_now_ticks || u64 requested_tick || u32 channel || u32 value`, big-endian, where `applied_now` is the boundary time at which the event was applied (state-determined, equal for any slicing). Phase 5 registers channels and gives them effect; no API change.
12. D6 settled while shaping this API [REC, MEDIUM]: core input is electrical, one channel per controller port, `value` is the byte the port presents (active-low, bits as read through the PSG I/O port). Logical to electrical mapping (disc direction, keypad, side buttons, ambiguous combinations) is a pure, host-side, separately tested helper outside the core; the runner scenario may use logical names or raw port bytes. Reverse if the shared contract (D13) must be consumed natively: add a second channel kind (for example `LOGICAL_MASK32`, a profile-table mapped to port bytes inside the core) as an append, no break. Rationale: the observable the guest has is the byte; a lossless logical mask cannot encode electrically ambiguous combinations (INP-02) without a matrix model that does not exist yet [UNK].
13. Digest domains: define 16 VIDEO, 17 AUDIO, 18 INPUT (rename the `IVS_DIGEST_RESERVED_*` macros to `IVS_DIGEST_VIDEO/AUDIO/INPUT`, same numbers). Each domain has two rows, `chain[32]` and `count u64`, zero at create and at power-on reset (a power cycle must equal a first reset), domain version 1 meaning "records as defined by the producing phase" (a producer phase that changes record framing bumps that domain's version; goldens record the version). The composite stays version 1 over domains 1..4 so no Phase 3 digest or golden changes; the runner reports composite plus all seven domain digests. `ivs_machine_state_digest` stops refusing 16..18. Instance grows by 120 bytes (3 x 40); update `IVS_MACHINE_BYTES`, the layout comment and the field table in one plan.
14. Honesty rule for empty domains: the runner and goldens print `video: none (no producer, domain v1)` and `audio: none ...`; a golden may not list an empty-domain digest as an observed value (gate-checkable: header key `domains` with `observed` or `none`). A match on a `none` domain carries no evidence.
15. Golden files are two kinds, both text with a `#` header the gate parses (steps `golden-header` with controls under `tools/check/controls/`): `*.expect` holds guest-state predicates, header `evidence_tier: original-diagnostic`, `oracle: independent-derivation` plus `derivation:` (path of the hand derivation, GI manual pdf page cites) so the expected value never comes from a run of this core; `*.digests` holds per-domain digests, header `evidence_tier: deterministic-repeatability`, `oracle: self-recorded`. Common header keys: `format: ivs-golden v1`, `id`, `profile`, `content:` (fixture ids with sha256), `scenario`, `bound_ticks`, `expected_stop_reason`, `api_version`, `digest_framing: IVSD v1, composite v1`, `domains:` per domain `observed|none` with version. Gate rules: tier id must exist in `data/tiers.json evidence_tiers`; `oracle: self-recorded` forces tier `deterministic-repeatability` (it can never back an accuracy claim); a `*.digests` file is regenerated only by an explicit runner `--update-golden` that rewrites the header date-free and prints a diff; the gate never regenerates.
16. State that must stay internal (not in any public header): the step seam and `ivs_cp1610_result` unit kinds, access logs, per-unit callbacks, breakpoints and run-until-PC (guest predicates are a runner concern over slices), `max_units`, gate setters, the memsys, `ivs_run_env`, and any wall-clock or progress callback. Guest observation for predicates is a separate, small public surface owned by the runner decision: `ivs_machine_inspect` (R0..R7, status, run state, fault reason) and `ivs_machine_peek(m, addr, count, out16)` defined as side-effect-free by contract from day one (Phase 6 makes that real for STIC reads); both allowed in OFF and POWERED, effect none, refusals BAD_ARG/BAD_HANDLE/OUT_OF_RANGE. [UNK] whether the runner-design decision keeps these names; the run API does not depend on them.

## 6. Slicing-invariance test design (minimal, in the existing `machine` suite)

State that makes a run resumable at every boundary: the whole instance (CPU 32 bytes including `dbd`, `halt_pending`, `prev_interruptible`, memsys, `time_ticks`, observation chains). Nothing about the call persists: no budget, no deficit, no target, no pointer, no event cursor (the caller holds the index; `events_consumed` advances it). Overshoot is not state: it is `now - T`, so a later slice whose target lies inside the previous overshoot is a no-op and the next unit starts exactly where a single run would.

Claim under test (proof sketch [INF]): the boundary sequence is state-determined; `run(T)` ends at the smallest `b_k >= T`; for `T1 <= T2` the sliced pair ends at the same boundary as a single `run(T2)`; for `T2 < now` it is a no-op.

Program: a project-authored stand-in decle list in the test (generated bytes, like Phase 3 stand-ins), loaded as EXEC through the boot-stub slot, covering unit lengths 4..10 CPU cycles (SDBD prefix unit, MOVR, MVO to RAM, a loop, DIS/EIS), ending in HLT; two variants (ends in HLT; ends in an unsupported-encoding guest fault). Synthetic env has channels 0 and 1 with a schedule of about 40 events: tick 0, ticks equal to a slice target, target + 1, a tick inside an overshoot unit, duplicates, a tick past the end (never consumed), unsorted-tail negative.
Reference: instance R stepped unit by unit with `run(now + 1)`; record the trace `(now, CPU-domain digest)` for every boundary and the composite plus all domain digests at 50 sampled boundaries.
Slicings on fresh instances: (1) target 1, 2, 3, ... until the end (about 2000 calls, mostly no-ops, exercising overshoot reuse); (2) fixed 7, 61, 1000, 59,736; (3) 200 increasing targets from a fixed-seed xorshift in the test (no host rand); (4) nonmonotone: repeated and decreasing targets interleaved; (5) `STOP_ON_HALT` set in every slice (stops at halt, later calls stop immediately).
Assertions per slicing: every slice end `now` is a boundary in R's trace and its CPU digest equals R's entry; at sampled ends the full composite and seven domain digests equal; at the end the whole-storage bytes of S equal R's (memcmp), `sum(elapsed_ticks)`, `sum(units_executed)`, `sum(events_consumed)` equal R's totals; overshoot of every call equals `max(now - T, 0)` and is below one maximum unit; the guest-fault variant stops with `GUEST_FAULT` and a further call makes zero progress (`units_executed 0`, time unchanged); the halt variant with the flag stops `CPU_HALTED` once, without the flag idles to the target. Cost [INF]: about 2000 units x CPU digest plus 50 x 113 KB hashing, well under 0.3 s per preset.
Named faults (appended to `data/expected/faults/machine.ids`, each shown to fail for its intended reason): `RUN_BUDGET_CARRY` (hidden remaining-budget carry between calls; fails slicing), `RUN_STOP_BEFORE_OVERSHOOT` (undershoot policy; fails the overshoot and `now >= T` assertions), `RUN_EVENT_AT_TARGET_ONLY` (events applied only when `tick <= T` instead of `<= now`; fails the input chain and consumed counts under straddling slices), `RUN_CAPACITY_AFTER_STEP` (output capacity checked after stepping; fails API-04 memcmp), `RUN_TARGET_UNCHECKED` (2^63 rule removed; fails the range rows), `RUN_FAULT_STEPS` (a FAULTED CPU is stepped again; fails the no-progress row). `STATIC_CARRY` already exists for the step seam and still applies.

## 7. Adversarial pass against the recommendation

- "Zero-length video and audio make API-04 untestable": partly true. The refusal and the exact-fit paths are real code and run through the synthetic env; what is not covered until Phase 6/7 is the real layout numbers. Mitigation: a gate assertion that Phase 4's real layout is all-zero (so a Phase 6 plan cannot change a size without touching the test) and a plan note that Phase 6/7 must add their real-profile rows to this same family.
- "An env seam is test-only logic that could drift from the public path": the wrapper must contain no branch beyond passing the profile's layout and channel table; a test calls both entry points with equal env and compares whole-storage results.
- "Chains hash empty domains, so digests look meaningful": addressed by 4.14 (`none` marker, goldens refuse to list them as observed) and by the claim ledger: no claim may cite an empty-domain digest.
- "Applying events at boundaries, not at the exact tick, is a timing lie": it is a stated quantization (up to one unit, tens of ticks) and equals hardware reality only as far as the CPU can observe input at unit granularity [INF]. The PSG port is sampled by a CPU read, which is itself a unit-internal access; sub-unit placement is a Phase 5 question (INP-01/02), and `requested_tick` is logged so a finer model can replace the rule with a domain version bump.
- "`STOP_ON_HALT` stops every call immediately": intended; hosts that want to keep time moving omit the flag. HALTED has no wake source before Phase 5/6; if one appears (STPST, BUSRQ) the reason priority and the idle rule are re-checked by the same slicing test.
- "Putting timebase and layout into `ivs_info` couples unrelated facts": it uses the append rule and avoids two more public functions and effect rows; if the struct grows past useful size, split later without breaking (append-only).
- "Composite staying at v1 means video, audio, input never enter the machine digest": deliberate; those domains are observations, and the memcmp of the whole instance (D-12) already covers them. A later composite v2 is allowed and would be an explicit golden refresh.
- "No relative budget will annoy hosts": a three-line host helper (`target = info.time_ticks + budget`) covers it; nothing in the core needs the form.
- "`INTERNAL` could hide real bugs as harness failures": it is mapped by the runner to the harness-failure outcome and fails the gate; a named fault proves the path is reachable.

## 8. Risks (top three)

1. Instance layout and digest table change (size 113,456 to 113,576 and three domains) touches many Phase 3 literals (`IVS_MACHINE_BYTES`, coverage test, relocation tests). Mitigation: one plan, fault-checked before and after; domains 1..4 and the composite digests must stay bit-identical (pin a Phase 3 composite literal first).
2. The API ships before real video, audio and input exist, so some fields (layout, channels, stop reasons 5 and 6) are speculative [INF]. Mitigation: only zero-valued, append-only fields; everything format-bearing is deferred to D7/D8/D6 owners, pre-1.0 so no ABI promise.
3. Hidden dependence of device or output behaviour on the target in Phase 6/7 would silently break slicing invariance. Mitigation: the slicing test runs against the real diagnostic in every later phase and the `RUN_*` faults stay in the inventory.

## 9. What would reverse it

- Evidence that a device must be advanced to a target inside a unit (a STIC steal or interrupt landing mid-instruction, Phase 2 D-01 reversal) forces micro-steps and a different overshoot meaning.
- A host that needs hard real-time slices of fixed tick length (an undershoot contract) would justify option 3.3 as an additional flag, not a replacement.
- A shared LibFuturo contract (D13) mandating a logical button mask would add a second channel kind (4.12).
- Measurement showing sub-unit input latency matters for the diagnostic or SCN-01 would change the event rule and bump the input domain version.
