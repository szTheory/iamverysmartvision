## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR content -> job summary | step output (paths, tokens) is rendered as markdown on GitHub |
| workflow file -> CI runner | a PR can edit the workflow to add caches, uploads, secrets or new runners |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | ci-summary.sh markdown | medium | mitigate | content comes only from gate-written files; FAIL lines fenced with backticks stripped; selftest `backticks-stripped`; no annotations emitted |
| T-04-02 | Repudiation | gate exit status via EXIT trap | high | mitigate | helper runs with `> /dev/null 2>&1 || :`, ends `exit 0`; selftest `unwritable-keeps-exit`; Task 1 verify with an unwritable path |
| T-04-03 | Information disclosure | caches/artifacts of build trees | high | mitigate | action allowlist (`actions/checkout` only), controls `ci-parity-action-cache` and `ci-parity-action-upload` |
| T-04-04 | Elevation of privilege | `secrets.` in a workflow | medium | mitigate | `ci-parity-secrets` token and control; `contents: read` unchanged |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | no package installs in this plan |
</threat_model>
