# Phase 4 Plan 14: project boot stub, tools/pack, stub path and trap tests, diagnostics review rule Summary

**The machine now boots from a power-on reset through a 22-word project boot stub that exists in the repository only as a hand-assembled, annotated text listing. `tools/pack` turns the listing into an 8192-byte EXEC image in the build tree of each preset, and suite `run` drives it through the public API: R7 at unit starts 1000, 1010, 1011, 1013, 5000; one INTR pulse lands in the trap, which writes `[035F] = 1` and halts at `100A`. `docs/diagnostics.md` writes down the grammar, the stub contract and the rule that the stub provides no routine or service to a cartridge.**

## What changed

- **Listing (D-26, D-28):** header keys `id boot-stub`, `kind boot-stub`, `contract 1`, `profile intv-2609-ntsc-family-p1`, `window 1000-101F`, the label, `entry 5000`, `stack 0340`; the grammar, the zero-fill rule, the derivation of every encoding with its manual page and the Phase 2 vector row that states the same encoding (`cpu.B.forward-plus-10`, `cpu.J.plain`, `cpu.MVII.ffff`, `cpu.MVO.address-ffff`, `cpu.HLT.sets-halt-pending`, `cpu.DIS.clears-intff`, `cpu.TSTR.base`), and the branch and jump arithmetic (`1010 - 1002 = 000E`; `5000` bits 15..10 = `010100`, second decle `0350`). 22 words, 12 non-zero. Each leaf row was checked against `data/cp1610/opcode-families.json` (0080 is TSTR over MOVR, 0240 MVO over MVO@, 02B8/02BE MVII over MVI@).
- **tools/pack (D-30):** one SPDX C17 TU, stdio only plus the core SHA-256 for the IVSC trailer (links `ivs_core`, `ivs_core_internal`, `ivs_warnings`, `ivs_san`); no install rule. It refuses, with a line-numbered message: a bad window header, a word line before it, non-ASCII bytes, a missing final newline, ADDR/HEX4 not 4 hex digits, a word above 03FF, bit groups not 10 digits or not equal to HEX4, a missing ROW or ASM, a non-contiguous address, an address outside the window, more than 4096 words; `--patch` refuses an address that is not a listed word. Checked by hand in the scratchpad: each refusal fires, the `--ivsc` trailer equals `cmake -E sha256sum` of the container minus its last 32 bytes, and `--patch 1001=000F` changes exactly that dump line.
- **CMake:** root adds `add_subdirectory(tools/pack)` before `tests`; `ivs_images` is an ALL target in both presets; `ivs_tests_run` depends on it and compiles `ivs_images.inc`; `ivs_fault_suite(run ...)` gains `run/run_stub.c`, the binary include dir and `GENERATED ${IVS_IMAGES_INC}`.
- **c-build:** the listed-source loop gains `'^tools/pack/.*[.]c$ ivs-pack-sources.txt'`. Probe: an untracked `tools/pack/extra.c` made the step print `-- FAIL c-build-unlisted-source: tools/pack/extra.c`; without it the step passed under dash.

## Cases

- `run.stub.path`: stub image (from the generated include) plus 2048 zero GROM bytes, no cartridge, power-on reset (state RESET_PENDING), then one `run(now + 1)` per unit with `units_executed == 1` and stop TARGET: R7 after the reset entry unit and after each following unit is 1000, 1010, 1011, 1013, 5000, state RUNNING; `intr_enabled == 0` after DIS and R6 = 0340 after the MVII. Non-vacuity: with the listing's displacement temporarily changed to `000F` (restored before commit) the case failed.
- `run.stub.trap`: at 5000 one INTR pulse (one unit stepped through `ivs_cp1610_step` with `lines.intr = 1`; the unit is an interrupt entry of 9 CPU cycles to 1004), then a public run with `IVS_RUN_F_STOP_ON_HALT`: stop CPU_HALTED, state HALTED, R7 = 100A, R0 = 1, `[035F]` 0 before and 1 after.
- `run.stub.halt-needs-follower`: unit by unit after the pulse: 1006, 1008, 1009 (HLT executed, still RUNNING), 100A (TSTR R0 executed, still RUNNING), then HALTED at 100A. With word 1009 patched to 0000 in an in-memory copy of the image, the CPU goes through 100A-100F, DIS and MVII #$0340,R6 and halts only at 1013 with R6 = 0340: zero fill is not a trap.
