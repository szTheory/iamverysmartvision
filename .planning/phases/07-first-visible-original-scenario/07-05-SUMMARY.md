## Deviations from Plan

**1. [Interpretation] Refusal cases are `runner.parse.edge.*`, not `runner.parse.refuse.*`.** `runner.parse.reasons-named` requires exactly one `runner.parse.refuse.<reason>` case per reason and `bad-content-kind` already has one; further refusals of a covered reason are `edge` cases (precedent `runner.parse.edge.zero-grom-as-cart`). The two new refusals (`content cart boot-stub-2`, `content grom boot-stub-2`) are therefore `runner.parse.edge.boot-stub-2-as-cart` and `-as-grom`.

**2. [Interpretation] The exec case serves the contract 1 bytes under the contract 2 name.** The contract 2 image is a Task 3 build product and the Task 2 test list has no `--c-include` change, so the fake host serves `ivs_img_boot_stub` as `boot-stub-2.exec`. The label must say contract 2 although the bytes are the other image, which is the property under test (D-30: the label comes from the symbolic kind only).

**3. [Design choice] One fuzz base names `boot-stub-2`.** Without it the seeded fuzz run never accepted kind 5, so the new exec-only invariant would have been vacuous; the video base now names `boot-stub-2` and the other bases keep `boot-stub`. A dictionary token `content exec boot-stub-2` was also added. All eight seeds and `reasons-covered` (46 distinct reasons) still pass.

**4. [Design choice] The recipe checker's tool table.** The plan says `tool_sha256` must equal the digest of the sources entry whose path is the tool's source; the checker needs to know which entry that is, so it carries `RECIPE_TOOL_SOURCES` (two tools) rather than a new manifest key. `tools/check/controls/_good/tree/` (listed in `files_modified`) needed no change: the control overlay supplies its own toy manifest and toy tool source.

**5. [Design choice] The regen case reads the listing id from the source header and the committed path from `listings.ids`**, instead of deriving a file name, so the later program fixture (`lamp-tone.asm`) needs no naming rule.

**6. [Process] A machine restart interrupted the run between the Task 2 gates.** The tree was intact; the Task 2 diff was reviewed against the plan, `sh`, `dash` and the container gate were run again on it, and the commit was made afterwards. No effect on the content.

No Rule 1 to 3 fixes; no auth gates; no package installs (T-07-SC). No gcc-only finding in this plan (both container runs passed first time).

## Decisions Made

- Keep the stub a stub: ten non-zero words, no service, no table, no trap logic beyond the hand-off; the contract text and the review rule are in `docs/diagnostics.md`.
- Count interrupt entries from outside (units ending at `1004`) so the control has no dependence on the routine's own memory writes.
- Do not assert the measured 179 or R6 `03F3`: they depend on the interrupt-request length and routine timing, and the claim is only the qualitative trap (D-10).
- No requirement is closed: SCN-01 stays Pending (program, scenarios, consumer replay come in 07-06 to 07-09).
