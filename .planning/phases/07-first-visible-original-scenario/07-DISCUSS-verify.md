## 0. Recommendation on one screen

1. **Freeze the scenario grammar (IVSS v1, report format ivsr 3). Add no assert subject.** Every predicate the success criteria need is already expressible: a timed input script (`input at_tick=`, up to 64 lines), multi-step progress predicates (`assert mem|reg` at several `run-to` steps), frame `hash`, `pixel`, `displayed`, `video count`, `psglog count` and record asserts, `audio at`, `audio emitted` [OBS, `docs/runner.md`]. Not touching the grammar avoids a report bump and a re-bless of every golden, which Phase 6 paid for, and avoids four parallel edits per new subject (parser, executor, `tests/expect-inc.cmake`, in-process family, fuzz corpus) [OBS].
2. **"The framebuffer differs in the expected region" is proved in three independent places, none new in the runner:** (a) the run asserts `frame <a> hash` and `frame <b> hash` equal the hashes of two hand-derived frame literals (idle frame F-S1, response frame F-S2) plus 6 to 10 `pixel` probes inside and outside the region; (b) a new token in the existing `video` gate step checks, on the literals only, that F-S1 and F-S2 differ exactly inside the declared rectangle and nowhere else (`video-frame-pair-region`, one control); (c) the installed consumer diffs the two delivered slots with its own code and counts changed positions inside and outside the rectangle (S4-5).
3. **Audio oracle without new code: silence is exact, steady level is exact, the log is exact.** Before the input the samples are all `0 0 0` and the PSG log holds only the guest's init writes; after it, the log has the hand-derived records (`addr`, `value`, `source`, never `tick`) and a channel with tone and noise disabled has the sample level equal to its 4-bit volume (rules PSG-R15 and PSG-R16 [OBS]), so `assert audio at <tick> A=<v>` is derivable without the tone phase. A tone's phase after a period write depends on the reload quirk (PSG-R08, 4096-step first reload) and is not asserted by tick. This is a design constraint passed to S-1 and S-2: **idle is silent and the first audible state is a constant-level window** (a tone may follow it). Reversal trigger and fallback: `assert audio changes` (S4-1).
4. **Oracle-first, as Phases 5 and 6.** Order of commits: derivation document and frame literals and `.expect` files, then the program listing, then the scenarios; asserts only on quantities independent of the emulator's policy defaults. Rule of the settling margin: no assert on the frame in which an input lands or on the next one; idle frames are asserted before the first input and response frames at least two frames after it; input events sit at least 10,000 ticks from any frame end; no `tick=` field in any `psglog` assert [INF from D-11 row-granular fetch, 06-CONTEXT].
5. **Scenario set (three process scenarios plus one variant):** `scn-pass` (scripted input, asserts all three channels, exit 0), `scn-idle` (same cartridge, no input, asserts the idle literals, exit 0; it replaces the timeout-style negative control of Phase 5 because it asserts what the idle program shows, not merely that it never halts), `scn-shift` (every event moved by +2,000 ticks, same `.expect` lines, exit 0: robustness against tick tuning) and optionally `scn-wrongport` (the same events on the other controller word, idle expectations). ## S4-1 Scenario grammar additions

Options.
- **A. Freeze (recommended).** Use what exists. Region and difference are expressed by two frame literals (hash plus pixel probes), progress by multi-step `mem` asserts, audio by `psglog` records and `audio at` in silent and constant-level windows.
- **B. Add `assert frame <n> rect <x> <y> <w> <h> ==|!= <colour>`.** Readable, saves pixel lines. Cost: parser (`runner/scenario.c`, 1,331 lines), executor (`runner/exec.c`, 1,395 lines), `docs/runner.md`, `tests/runner/runner_parse.c`, `runner_exec.c`, `tests/expect-inc.cmake` and the in-process macros, fuzz seeds, a new reason token, a fault and a control. It is sugar: a full-frame hash against a hand literal is strictly stronger than a rectangle, and 6 to 10 `pixel` lines give the same readable probe. Reject.
- **C. Add `assert frame <a> differs <b> within <x> <y> <w> <h>` (a relative diff).** The literal reading of criterion 3. Weaker than A as an oracle (two emulator outputs compared with each other; no value is hand-derived), and the same cost as B. Reject; the relative form is provided by the metamorphic judge (S4-3) and the consumer-side diff (S4-5) without runner code.
- **D. Add `assert audio changes ==|!= <n>` (delivered level-change count so far; the runner already counts it for `output.audio.changes`).** Cheap (about 25 lines plus the four parallel edits). Useful only if the program's first audible state is a toggling tone and no constant-level window can be designed. **Trigger to adopt D:** S-1 or S-2 reject the silent-idle plus constant-level-first design, or the `audio at` derivation needs the tone phase. Adopt only the `==`/`!=` form with `0` derivable (silence), not a derived non-zero count.
- **E. `at_frame=` for input.** Stays refused: frames are nominal, not frame events (D-09), and a tick is the only unit under which "a read inside the unit that began earlier sees the old state" (C67) is stated exactly [OBS, `docs/runner.md`].
- **F. Scenario macros or loops.** Reject: the parser is a pure, allocation-free function with fixed caps and a fuzz target; a macro layer is a second language.

Convention instead of grammar (documented in `docs/runner.md` and the derivation):
1. **Input events** are written in `ticks`, one per line, each stating both controller words (the parser refuses a single word) [OBS, 06-13 deviation 1]; the words are indexed by PSG port, so `c0` is the port at `$01FE` (06-CONTEXT, 05-05).
2. **Margins:** every event is at least 10,000 ticks from any frame end `E_k = 59,736 (k + 1)` and at least 600 ticks from the next event (the Phase 5 rule, far above one poll loop) [OBS for E_k and the 600-tick rule; INF for the 10,000 figure: about a sixth of a frame, far above the 31-cycle (124-tick) error of the Phase 6 cycle budget].
3. **Run-to bounds** sit mid-frame, at least 10,000 ticks from a frame end and from the end of the last scripted effect, so a later phase that changes bus-steal accounting (Phase 8) moves no assert.
4. **Cap budget:** at most 56 asserts and 56 input lines per scenario (cap 64, headroom 8), at most 1,000 expected capture entries for `psglog` and `audio` (cap 4096, 4x headroom; with a tone of period P the half period is 16 P ticks [OBS, PSG-R05], so entries in N ticks are about N / (16 P)).
5. **Never-halting vs halting program:** both work (`run-to <n> ticks` with the default target stop, `assert halted == no`). [REC to S-1/S-2, not decided here] Prefer a program whose scripted last input quits it to a `HLT`, because then `stop halted` is a stronger "ran the script to its end" marker, `scn-idle` ends at its bound with the guest still alive (assert `halted == no`), and the Phase 5 idiom (halt only when the input arrives) is reused.

Reversal evidence: a design review of S-1 shows the response frame cannot be placed two frames after the input without exceeding 16 captured frames (capture window), or the asserts exceed 56; then adopt B or raise caps in a dedicated plan. Risk of A: a reviewer reads criterion 3 literally ("differs in the expected region") and finds no differential assert in the run; mitigation is the three-place proof of recommendation 2 and a one-line mapping table in the verification record.

## S4-2 The non-circular oracle for the video, progress and audio expectations

What "non-circular" can and cannot mean here [INF]. The expected values must be derived from the program's specification and from the hardware documents, never from a run of the emulator. They cannot be independent of the author's reading of the CP-1610 semantics (shared misreading, AGENTS.md "shared-core agreement is not an independent oracle"). The honest tier is therefore `original-diagnostic` plus `independent-derivation` for the `.expect` and `provisional` for every claim, exactly as Phases 5 and 6.

Layers, from strongest to weakest independence.
1. **Program-semantics derivation, written before the program** (as `docs/input/diag-ctrl-psg-1-derivation.md`, `docs/video/diag-stic-1-derivation.md`): for each scripted event, the RAM words and BACKTAB cells the program must hold, the PSG register writes in order, the amplitude per channel, and the settle frame. Quantities that need a cycle-exact schedule (the tick of a write, the exact ISR entry) are not derived and not asserted.
2. **Frame literals** F-S1 (idle) and F-S2 (response), plus F-S3 if a third state exists: authored as `.frame` files with cell annotations and a `sha256-text` key (the Phase 6 form). Derive F-S2 as a delta of F-S1: "the 8 x 8 block of the changed cell replaced by the card pattern rows", so the derivation is a few lines and the popcount conservation check covers it. The hash in the `.expect` is the literal's key (tie checked by `video-frame-hash-expect-drift`).
3. **Pair-region check on the oracle files themselves** (new token `video-frame-pair-region` in `tools/check/video.cmake`, header line `# pair: <idA> <idB> rect x y w h` in the `.expect` or the frame header): the planes differ at exactly the positions inside the rectangle and the number of differing positions equals the derived count (popcount of the card pattern XOR the background fill). Pure text, no emulator output read. One control (`video-frame-pair-region-drift`: a toy pair with one extra differing pixel outside the rectangle fails).
4. **Constant-level audio window** (S4-1 recommendation 3): level = volume index because a channel with both tone and noise disabled is a constant 1 (PSG-R15) and the fixed amplitude is bits 3..0 (PSG-R16) [OBS rule text; the rule set is tier 4 and inference per Phase 5, so the claim stays provisional]. Silence before the first volume write is exact (reset state: all registers 0, PSG-R21).
5. **Blind re-derivation** [REC, same protocol as Phase 6 D-02 and Phase 5 second reads]: a fresh agent receives only the written program specification (not the listing, not the `.expect`) and produces the expected marker values, the PSG write list and the changed-cell rectangle; disagreements are resolved against the manual and recorded. Cost is one agent turn, no gate code. The agreement is recorded in the derivation document; it is not a claim of hardware accuracy.
6. **Self-recorded goldens** (`.digests`): repeatability only, labelled as such (tier `deterministic-repeatability`, oracle `self-recorded`).
7. **Metamorphic checks** (S4-3): relations between runs, no expected values at all.

Commit-order discipline [OBS from 06-13]: the `.expect` and literals are committed before the scenarios and the first scenario run. Phase 6 recorded the order by hand in the SUMMARY and noted one deviation (an unrecorded run preceded the commit). [REC] Record the order in the plan task acceptance (`git log` order of the oracle commit and the scenario commit) and name any deviation in the SUMMARY; a mechanical gate check is not possible (shallow clones, history rewrites) and is not recommended.

Settling-margin rule, stated as a derivation rule, not as a tolerance. Rendering is frame-granular at `E_k` from row-latched BACKTAB (D-11) and the bus-window policy is a labelled default (C82 to C95) [OBS 06-CONTEXT]. Therefore (a) frames before the input frame are asserted as idle; (b) the frame containing the input tick and the next one are not asserted (the guest's ISR and the fetch windows decide which of them shows the change, and that is policy, not evidence); (c) frames from input frame + 2 on are asserted as response. If the program redraws every frame, the response literal is stable from that frame on and one literal serves every later frame.

Progress predicates (SC2). Assert at three or more `run-to` steps, not only at the end: before the first event (idle values), after each scripted phase (hand-derived values that differ from the previous step), and at the halt or the final bound. At least one predicate must be a counter or position that moves by an amount equal to the number of pressed events (so the value proves cumulative state, not a flag). [INF] This is the register-signature idea of blargg and Mooneye style tests [BG]: a predicate over guest state that a wrong program cannot reach by accident. A screenshot hash alone is the failure mode those ecosystems moved away from [BG].

Footguns found.
- **Events after the last bound are silently ignored.** `input.consumed` is reported next to `input.events` [OBS]; no assert subject reads it. [REC] The differential judge requires `input.consumed == input.events` for `scn-pass` (S4-3), and the shape lint requires the last `input` tick to be below the last `run-to` target.
- **An idle program that already sounds or draws** makes "input changes the output" vacuous (the Phase 5 diagnostic is audible when idle). Required design property: idle is silent and shows F-S1.
- **Capture overflow** turns a scenario with a fast tone into a harness failure rather than a fail; S4-1 item 4 sets the budget.
- **Frame index versus time:** `frame <n>` is the n-th delivered slot, whether or not the display was enabled [OBS]; asserting `frame <n> displayed == yes` for the idle and response frames closes the case "the display never came on and the plane is all border colour".
- **Hash of a frame with a blank position cannot be hash-asserted** (`hash-needs-colors-only`) [OBS]; the program must not leave blank positions in the asserted frames (no blanked cards).

Reversal evidence: if the blind re-derivation disagrees in a place the manuals do not decide, that value moves out of the `.expect` into the discrepancy log as `unknown-default-chosen` and the assert is dropped, as in Phase 6. Risk: the author's program and derivation share a misreading; the claim text says so (S4-6).

## S4-3 Scenario set, variants and the metamorphic differential judge

Scenarios (ids illustrative, S-1 names the program): all use the project boot stub, the zero GROM and the cartridge image built from the listing, profile `intv-2609-ntsc-family-p1`.
- `scn-pass`: script of 6 to 12 events in 3 to 4 phases; 4 steps with progress asserts at each step end; `capture video <first> <count>` covering the idle frames and at least one response frame (count at most 16, 15,296 bytes per slot); `capture psglog` and `capture audio` only if used; asserts: markers, `frame displayed`, 2 hashes, 6 to 10 pixels, `video count`, `psglog count` and records, `audio at` silent and level windows. Outcome pass, exit 0. Tier on the `.expect` header: `playable-guest-progress`, oracle `independent-derivation`.
- `scn-idle`: same cartridge and capture lines, no `input` line, run to the same final bound; asserts: markers at their idle values, `halted == no` (if S-1 halts on a quit input), `frame` literals F-S1 for every captured frame, `psglog count` equal to the init-only count, `audio at` all `0 0 0`, `audio emitted` equal to the sample count of the bound. Pass, exit 0. Replaces `diag-ctrl-psg-nokey`'s timeout idiom: a timeout shows only that the guest did not halt, whereas this asserts that nothing visible or audible changed. Own `.expect` and `.digests` (a second `independent-derivation` file).
- `scn-shift` (variant, no own `.expect`): the `scn-pass` text with every `input` tick +2,000, identical assert lines; passes only if the predicates are not tuned to tick values. A throwaway probe at planning time sweeps shifts of +-1,000, 2,000, 5,000 and 10,000 and records the pass band in the derivation; CI keeps the one variant (+2,000), which is inside the margin of S4-1 item 2 by construction. [INF] A cheaper alternative is the existing "order" idiom (each event split in two lines one tick apart, as `diag-ctrl-psg-order`), which tests same-tick ordering rather than robustness; the two are different failure classes. Take `scn-shift` for the margin class; skip a second "order" scenario because Phase 5 already owns that class.
- `scn-wrongport` [optional]: the `scn-pass` events with `c0` and `c1` swapped; asserts equal to `scn-idle`. Catches a swapped-port decode in the program or the core (the words are indexed by PSG port, not by player, a recorded footgun). Include only if S-1 polls one port; cost one process case.

**Differential judge** (suite `runner-process`, after the pass and idle reports exist in `build/gate/<preset>/runner/`) [OBS: reports are left there per scenario]. A pair inventory `data/expected/scenario-pairs.ids`, line `<passId> <idleId> <must-differ keys> <must-equal keys>`. Rules for `scn-pass`/`scn-idle`: must differ: `digest.video`, `digest.audio`, `digest.psglog`, `digest.input`, `digest.mem`, `output.psglog.records`; must equal: `slot.*.sha256` lines (same images), `digest.images`; `input.consumed == input.events` in the pass report, both 0 events in idle; `output.audio.changes == 0` in the idle report. Judge self-controls on the Phase 4 pattern (fake report pairs: video digest equal; consumed below events; idle with audio changes), each rejected for its stated reason; 3 in-suite ids, no gate-control directory. [INF] This is a metamorphic test: it needs no expected value and survives any later change of the literals; it fails if input is ignored or if the program ignores one channel.

Alternatives considered. (a) Put the relation in a runner assert (`assert digest video != <hex>` against the idle digest): the hex is self-recorded, so it is a golden dressed as an assert and breaks on every unrelated change; reject. (b) A second scenario file chaining both runs: the runner is one instance per scenario by design [OBS]; reject.

Reversal evidence: if an idle run is ever allowed to be audible for design reasons (S-1), the `output.audio.changes == 0` clause is dropped and `digest.audio` must-differ stays. Risk: a judge reading flat `key value` reports must tolerate the `ivsr` version; it reads only keys of the closed table and is covered by the existing report-format self-controls.

## S4-4 Program mutants and negative controls

Mechanism [OBS]: the inventory pattern of `data/expected/diag-mutations-stic.ids` (scenario column, comma-joined address, from and to word lists, clause, outcome, exit), `ivs_pack --ivsc <listing> <out> --patch ADDR=HEX`, judged by `run_mutant` in `tests/runner-process-tap.sh`; the loop checks that the word at the address in the unpatched listing equals the `from` column before patching, so a listing edit that moves an instruction fails the case instead of mutating something else. New inventory `data/expected/diag-mutations-scn.ids` (copy-paste of the STIC one) plus one optional column.

**New optional column `fails=<j,j,...>`** (the complete set of failing assert numbers). `run_mutant` already prints the report; the judge reads `step.<k>.assert.<j> fail` lines (about 10 lines of awk) and compares the set. Reason: the current judge checks only `outcome.detail`, the first failing clause. A video-only mutant that also trips an audio assert looks identical to a good one, and an over-coupled `.expect` stays invisible. Use the column for the three channel-isolation mutants only; the rest keep the first-clause form. Hand-ordered `.expect` (markers, then frames, then log, then audio) keeps the first clause equal to the channel.

Mutant list (classes, each one distinct failure class; actual words depend on S-1 and S-2, so the table gives the class and the intended clause, as the earlier inventories did before the words were derived).
| ID | Class | What changes | Scenario | Intended failing clause |
|----|-------|--------------|----------|-------------------------|
| SCN-KEY-CONST | input decode | the compare constant of the key or direction test (patched immediate) | pass | first `mem` progress assert after input; frame and log asserts also fail (set judged: all three channels follow the missing progress) |
| SCN-PROGRESS-STORE | progress write | the store address of the marker or counter | pass | `mem <marker>` only; fails set = marker asserts, frames and log still pass |
| SCN-CELL-ADDR | video write | the BACKTAB cell address or card word written on input | pass | `frame <n> hash` and region pixels; `fails` = frame clauses only |
| SCN-VOLUME | sound value | the volume or period immediate written on input | pass | `psglog <i> value=` and `audio at`; frame and markers pass |
| SCN-SOUND-UNGATED | sound gate | the guard branch that makes the sound conditional on input is removed or inverted | idle | `psglog count` and `audio at` of the idle scenario (the idle control shown able to fail; the pass scenario alone would pass it) |
| SCN-ISR-REARM | sustained display | the per-frame display strobe or interrupt return (S-2 names it) | pass | `frame <n> displayed == yes` of a later frame (display not sustained) |
| SCN-DELAY-NEG | negative | a loop count or delay that moves only timing | pass | none: pass, exit 0 (shows asserts are not tuned to exact ticks; included because Phase 5 did) |

Rules carried from Phases 5 and 6 [OBS]: a mutant that could lengthen a loop is never judged `guest-fail` (judge `timeout` with the budget detail); expected clause written in the inventory before the mutant is run; one wrong clause and one wrong `from` word are made to fail the case once and restored (recorded in the SUMMARY). [INF] Mutation operators are hand-chosen to cover the input, state, video, audio, gate and sustain classes; no automatic mutation generator is warranted for a program of a few hundred words.

Negative controls beyond mutants.
- `scn-idle` and `scn-wrongport` (S4-3) are the behavioural negatives.
- Gate controls (directory form, `tools/check/controls/<name>/{overlay,EXPECT}`): `video-frame-pair-region-drift` (S4-2), `golden-shape-no-progress`, `golden-shape-no-input` (S4-3 shape lint, token names illustrative). Three controls, all pure: about 0.07 hosted cpu-s each [OBS unit cost from CI-EFFICIENCY].

## 2. Adversarial pass on the whole recommendation

- **"Freezing the grammar leaves criterion 3 under-asserted."** Counter: the run asserts two full-frame hashes equal to independent literals and probes pixels; the region difference is a property of the literal pair (gate-checked) and of the consumer diff. If a reviewer insists on an in-run differential, option C is a one-plan addition with its four parallel edits, and nothing else in this recommendation changes.
- **"Hand-derived frames are expensive."** Counter: the delta form (one cell block) costs a few lines and the Phase 6 conservation check guards it; a frame generator would be a second renderer and is exactly the shared-core oracle the project forbids (06-CONTEXT D-02: no second renderer).
- **"Six mutants and a judge column are over-building."** Counter: they are the only evidence that each channel's asserts can fail, and each is one process case; the cost is inside the 10 cpu-s budget with levers named. If the first hosted row shows over-budget, the first fallback keeps all classes and halves their cost.
- **"A never-halting program makes the scenario nondeterministic at the bound."** Counter: machine time is exact; the bound is a tick, the guest state at a tick is deterministic, and asserts sit mid-frame with margins. The slice-invariance variants (1 and 7 ticks) prove it for `scn-pass`.
- **"`scn-idle` and `scn-pass` share the program, so a program bug makes both pass the wrong thing."** Counter: the differential judge and the hand-derived literals are independent of each other; a bug common to both would have to give the derived values anyway, which the oracle layers catch.
- **"The consumer replay duplicates the runner."** Counter: that is its job (PKG-01 independence: separate build, separate code, installed headers only); it differs by checking the region diff and the audio and log values with its own decoders, and by driving the core frame by frame.
- **Lessons from other ecosystems [BG, not re-fetched].** Test ROMs for other consoles (blargg, Mooneye, the NES and Game Boy suites) report pass or fail through a register signature or memory marker and treat screenshot hashes as a regression aid; replay-movie suites (TAS style) key on input timelines plus frame hashes and suffer from hashes that encode every unrelated rendering change. The shape here follows the first style for the claim and keeps the hashes bound to independent literals and relations rather than self-recorded values. Scripted-input regression suites in other emulators commonly hit the "event after the end of the run is ignored" and "idle already animates" failure modes found above.
