**The project mini-assembler `ivs_asm` exists as a registered, never-installed C17 tool of 806 lines, and the two twins it assembles reproduce the 78 hand-typed words of the boot stub and `diag-cpu-1` word for word (and column for column: ADDR, HEX4, BITS and ROW of all 78 lines equal the hand listings), with a comparison shown able to fail; no hand slip and no encoding escape was found.**

## What was built

- **Language** (A-15, A-01): the repository dialect. `# key: value` header block copied unchanged (`# window: AAAA-BBBB` required and checked against every word, `asm-window`); `;` comments; `label:` global labels; `NAME EQU expr` (earlier symbols only); `ORG` forward only (the gap is zero words, row `HLT`, text `fill`; the first `ORG` comes before any word or label); `+` and `-` left to right with every partial result 0 to 65535; `$` hex, decimal, symbols of at most 31 characters; reserved words refused.
- **Listing**: header lines, `# generated by ivs_asm from <path>; edit the source, not this file`, one `# sym: <name> <ADDR>` line per label (never `# label:`), then `ADDR HEX4 BITS ROW ASM` per word, BITS grouped as the hand listings group them (4+3+3, 4+2+4 for a branch, 2+4+4 for an operand word, 2+6+2 for the second jump decle), `-> ADDR` on branch and jump lines. Written beside its target as `<listing>.tmp` and renamed; a refusal removes it, so no output file is left.
- **Rows covered (19 mnemonics)**: HLT, EIS, DIS; INCR, DECR, GSWD (R0 to R3); TSTR, CLRR, MOVR, ADDR; MVO (direct, address at most 03FF); MVI@ (indirect R1 to R5; R0 is `asm-register`, R6 and R7 are `asm-spelling` naming PULR and MVII); PSHR, PULR; MVII, ADDI (immediate at most 03FF, else `asm-imm-sdbd`); B and BNZE (forward `target - (pc + 2)`, backward `(pc + 1) - target` with S = 1, displacement at most 03FF, else `asm-branch-range`); J (three decles). `MOVR` with equal registers or into R7 is `asm-spelling` (TSTR, JR). EIS is not used by either twin; its decle `0002` and `B $1001` (`0220 0000`) and `MVI@ R1, R2` (`028A`) were compared with the Phase 2 vector corpus in a scratch run (agreed); the pairs corpus of plan 07-04 makes that a committed check.
- **Tokens implemented (17 of the 20 listed in S3-8)**: `asm-syntax`, `asm-mnemonic`, `asm-operand-count`, `asm-operand-kind`, `asm-register`, `asm-symbol-undefined`, `asm-symbol-duplicate`, `asm-symbol-reserved`, `asm-expr`, `asm-imm-sdbd`, `asm-direct-range`, `asm-branch-range`, `asm-org`, `asm-window`, `asm-spelling`, `asm-header`, `asm-limit`. Not yet present: `asm-imm-range`, `asm-sdbd-target`, `asm-decle-range` (they come with `SDBD` and `DECLE` in plan 07-04). One refusal is one stderr line `ivs_asm: <token>: <source path>:<line>: <detail>`.
- **Limits** (`asm-limit`): 131,072 source bytes, 4,096 lines, 255 bytes per line, 4,096 words, 256 symbols, 32 header lines. Bytes outside printable ASCII and tab, and any CR, are `asm-syntax`. No `getenv`, time, locale or other file.
- **Registration** like `tools/pcm`: `add_subdirectory(tools/asm)` before `enable_testing()`; the fifth list `ivs-asm-sources.txt` in `c-build.sh` (header comment updated); `tools/asm` in the SPDX rule of `integrity.cmake`; the toy tree's fifth list line and `tools/asm/good.c`; the two controls in `runner-hygiene.ids`.
- **Suite asm** (shell TAP like `pack-tap.sh`, under the existing `c-tests` step, no new step, job or dependency): the twin is assembled with the working directory at the source root and a relative path; `ivs_pack --dump-words` of the generated listing is compared byte for byte with `ivs_pack --dump-words` of the committed hand listing. `asm.judge.mutated-twin` changes `#STACK, R6` to `#STACK, R5` in a temporary copy of the boot stub twin and requires the same comparison to fail with a diff of exactly `< 1011 02BD` and `> 1011 02BE` (`judge-vacuous` or `judge-wrong-reason` otherwise). `asm.repeat` assembles the `diag-cpu-1` twin twice and requires two identical, non-empty listings.

## Deviations from Plan

**1. [Interpretation, plan wording] Task 2 changed no C source for rows.** The tracer text says the task "needs only the rows of the boot stub", and Task 2 says to extend the table to every row `diag-cpu-1` uses. The table is static data and the rows (ADDR, ADDI, INCR, DECR, GSWD, CLRR, MOVR, PSHR, PULR, MVI@, BNZE, the backward branch) were written into the Task 1 table together with the operand classes, so Task 1's commit already held them (untested by Task 1's own suite until Task 2). Task 2 added the second twin, `asm.repeat` and the ids, and fixed one message. Shifts and `PSHR` aliases of the plan text: `diag-cpu-1` uses no shift, so none is in the table; `PSHR` and `PULR` are mnemonics of their own in the dialect.

**2. [Interpretation] `docs/packaging.md` had no `ivs_pack` statement to sit beside.** The sentence names `ivs_pack` and `ivs_asm` together under the paragraph that lists what is not installed.

**3. [Design choice recorded] File and usage errors carry no token.** The format `ivs_asm: <token>: <source path>:<line>: <detail>` is for source refusals. A missing source, a bad path or an uncreatable listing print a plain `ivs_asm: ...` line (as `ivs_pack` does), so the pinned token inventory of plan 07-04 stays the 20 tokens of S3-8.

**4. [Design choice recorded] Two requirements the plan did not state.** The source path must be relative with only A-Z a-z 0-9 . _ / - characters and must differ from the listing path (no absolute path in any generated listing; the source cannot be overwritten by a swapped argument pair); the header must carry `# window:` (the S3-5 extent check needs it and the packer needs it).

**5. [Process] A throwaway scratch harness.** The refusal probes, the checker run on the generated listings and the mutation sweep ran from scripts in a scratch directory outside the repository; nothing from them is tracked.

No Rule 1 or Rule 2 fixes were needed; no auth gates; no package install (T-07-SC).
