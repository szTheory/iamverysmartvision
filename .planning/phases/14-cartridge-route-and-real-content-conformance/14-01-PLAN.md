    The seven refusal cases are minted by a loop over `data/expected/flat-refusals.ids`, exactly the
    `asm.neg.<token>` idiom, so a token added to the pin without a case, or a case for an unpinned token,
    is a finding rather than a silent gap. Each case is one `flatwrap-neg-<token>` scratch directory and
    asserts **both** halves in the same case, because criterion 2 pairs them: the refusal is exit 1 with
    exactly one stderr line carrying that token, empty stdout and **no output file**; the boundary positive
    is exit 0, one 64-hex stdout line, an output file of the exact expected size, and — where the pair is
    about a value — the value read back from the container. The pairs, with the arithmetic that makes each
    one truthful:

    - `flatwrap-length`: 1 byte refused; 2 bytes accepted as one word.
    - `flatwrap-word-range`: input bytes `04 00` refused; `03 FF` accepted (and the container's word is
      `03FF`).
    - `flatwrap-words`: 65,537 words refused with `flatwrap-words`; **65,536 words is refused with
      `flatwrap-cross`**, not with this token. This is the recorded deviation from criterion 2's literal
      wording and it is arithmetic, not preference: `IVS_IVSC_MAX_SEGMENT_WORDS` is 65,535, so a
      one-segment writer cannot encode 65,536 words at all, and `$4000 + 65536 = $14000` crosses `$10000`
      first. The case asserts the exact token each input produces, so it pins the count rule's threshold at
      65,536 and proves the tool never writes a wrapped or zero `len_words`. The real acceptance boundary
      is `flatwrap-cross`'s pair.
    - `flatwrap-base`: base `3FFF` refused; `4000` accepted.
    - `flatwrap-cross`: 49,153 words at `4000` refused; 49,152 words at `4000` accepted and its last word
      sits at `$FFFF` (`$10000 - $4000 = $C000 = 49,152`).
    - `flatwrap-output-tree`: `$ROOT/build/<name>.ivsc` refused; `$TMPDIR/<name>.ivsc` accepted. The case
      also runs a path whose parent is reached through a `..` spelling and one through a symlink to a
      directory inside the tree, so the physical-parent compare is exercised and not just the literal
      spelling — the `owner-run.sh` ids' own technique.
    - `flatwrap-output-exists`: an existing path of any kind refused **and byte-unchanged** (compare a copy
      taken before the run); a new path accepted. The byte-unchanged half is the point of the exclusive
