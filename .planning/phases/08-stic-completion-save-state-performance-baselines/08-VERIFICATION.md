## Goal achievement

The goal is met in the sense the gate can test, on the terms of the caveats below. **STIC (VID-05):** MOBs, border extension, horizontal and vertical delay and collision registers each have a single-feature check against an expectation that was derived by hand and committed before any code (ten frames F-M0 to F-M9, the 48-line MOB bit-role literal, rules STIC-R37 to R50, a collision truth table, a blind second read), and the original program `ivs-diag-stic-2` shows each feature through the runner with five single-feature scenarios and an idle control, hand-derived asserts, two pair lines and six release-preset mutants; what the sources do not settle sits on the explicit `unknown-default-chosen` list (C107 to C110 and the C87 pins), each with a flip control, a claim exclusion and an owner hand-off. **State (STA-01, STA-02):** one table of 88 rows with a snapshot class is the single serializer for the state digests and for the container IVSN v1 (4,299 bytes for the first profile: a 612-byte header, seven sections, a SHA-256 trailer, never any image byte); a snapshot carries the format version, the schema digest, the profile identity and the three image-slot identities; restore validates everything into a probe before it commits, and a corrupted, wrong-version, wrong-profile or wrong-image snapshot is refused with the instance unchanged (a 406-row read matrix, a 180-row restore matrix, a corruption and fuzz family); snapshot, restore and run equals the uninterrupted run at 18 named hard points, including mid-frame, mid-SDBD and three bus-steal variants, over a written 88-row hidden-state checklist whose every row has a witness; the runner hook `--roundtrip-at-ticks` and a fifth installed-consumer replay carry the same property to the host surfaces. **Performance (PRF-01):** four named workloads are verified against committed goldens before any clock is read, a mismatch is refused with exit 15 and a row without a figure, and throughput, latency and CI time are reported in separate groups, with no threshold anywhere. **Release (REL-01):** the release machinery (workflow, scripts, readiness generator, rehearsal) and the close record at stage 1 exist; the stale text is swept.

What the goal does not include, and the record does not claim: that any console behaves as the STIC or state model says (D10 is not performed, and the MOB, collision and delay bits rest on one tier 4 lineage); that any real EXEC or GROM image was run (D11 is not performed); that a person saw a frame or heard a sound; that any timing figure is right; that a snapshot from one build restores in another (IVSN v1 is exact-build); that a benchmark figure is more than repeatability information; or that anything was published (the release is not started; REL-01 stays Pending until stage 2).

## 3. Accepted caveats

- **One tier 4 lineage for STIC.** No tier 1 to 3 page prints any MOB, collision, delay or border-extension bit; every rule rests on one community lineage, every expected value is `source-expectation`, and the claims CL-0025 to CL-0027 are provisional with exclusion lists. A primary page or a D10 capture is the resolver.
