    (a) `tools/inspect/inspect_dis.c`, one new translation unit, added to `IVS_INSPECT_SOURCES` in
    `tools/inspect/CMakeLists.txt` (the `ivs-inspect-sources.txt` writer follows the list automatically, so no other

    The command is `dis <listing> --out <file.asm>`, with the same exit statuses and the same output ladder
    `18-02` established (tree refusal, then exists, then exclusive create, then a short write removing what it
    created). Reading a listing: skip blank lines and `#` lines, and copy **only the leading run of
    `# key: value` lines whose key is one of the eight `ivs_asm` accepts** (`id`, `kind`, `contract`, `profile`,
    `window`, `label`, `entry`, `stack`), verbatim and in order. Copying every `#` line is wrong and was measured
    wrong: `tools/asm/asm.c:924-957` ends the header block at the first line that is not one of those keys, so the
    boot-stub listing's bare `#` at line 9 and its prose lines make a verbatim copy fail with
    `asm-header: header lines belong at the top of the source` before a single word is assembled - the round trip
    would then fail for a reason that has nothing to do with the disassembler. Copying only the accepted keys keeps
    the required `# window:` line and drops the commentary, and the header rule is pinned in the frozen page's
    `## Disassembly` section. Then each word line is split on whitespace. The first field is the address and the
    second the word; the `BITS` column is space-separated into a variable number of groups, so the row is found by
    consuming every following field whose characters are all `0` or `1` and taking the next one - the row is either
    `-` or an upper-case row id, and nothing else in the line can be mistaken for it. A line whose row is `-` is an
    operand word of the instruction above it and is not emitted as its own line; the rest of the line after the row
    is the `ASM` text.

    The mnemonic is the row field verbatim, lower-cased only for the refusal token's detail - it is the listing's
    own leaf row id, so no mnemonic table exists. A row the emitter does not know is refused with
    `inspect-dis-row`, naming the row and the address, **before** the output is created, so a failed `dis` leaves no
    file.

    The operand derivation is three cuts on the `ASM` text, in this order, and the order is the whole rule:

    1. Cut the trailing note at the first run of two or more spaces. This must come first, because the listing
       separates the `ASM` column's instruction text from its note with a run of spaces and an operand's own
       separators are single spaces - so cutting here yields exactly the instruction text.
    2. Cut the branch or jump target annotation at ` -> `. The listing writes it with single spaces on both sides
       (`B $1010 -> 1010`, `J $5000 -> 5000`), so it survives cut 1 and would otherwise be emitted as operand text.
    3. Drop the leading token **only when it repeats the row field**, and what remains is the operand. Where it does
       not repeat the row - the listing's zero-fill rows carry `fill (zero, unreachable)` in the `ASM` column -
       that column is a note and not instruction text, so the mnemonic is emitted with no operand.

    Do not skip cut 3: the listing's `ASM` column already carries the mnemonic (`B     B $1010 -> 1010`), so
    emitting the row and the `ASM` text together produces `B B $1010` and `HLT HLT`, which `ivs_asm` refuses as an
    operand-kind error - a stand-in or an emitter built that way never assembles, and both the round trip and the
    constant-mnemonic id then fail on a correct implementation. The derived result on the boot-stub corpus is
    `B $1010`, `HLT` (eight times, the fill rows), `MVII #$0001, R0`, `MVO R0, $035F`, `TSTR R0`, `DIS`,
    `MVII #$0340, R6`, `J $5000` - measured this session against this tree's `ivs_asm` and `ivs_pack`:
    sixteen instruction lines, 22 words, dump byte-identical to the input listing's.

    The operand is written after the mnemonic on an eight-column indent. Where the address is not the previous
    instruction's address plus its word count (itself plus its following `-` rows), emit an `ORG` directive with the
    address in four upper-case hex digits preceded by `$`, before the first instruction and at every such gap, so a
    gap or a jump in the listing is preserved rather than silently packed. Record in the file's header comment that
    the mnemonic is the listing's own row and the operand text its own asm column, that the only thing this file
    knows is the three cuts, the header-key filter and when to emit `ORG`, and that the round trip through
    `ivs_asm` is what proves them - so a later listing with a different annotation fails loudly instead of
    disassembling wrongly.

    If the cuts prove not deterministic on the corpus during this task, fall back to deriving the operand from the
    `BITS` field groups plus the following `-` rows' words (the research's option 1) and record the fallback as a
    deviation with the reason; do not weaken the refusal, the `ORG` rule, or any of the four guards below.

    `tests/asm/twins/boot-stub.asm` is assembled and dumped to `$tmp/twin.words` with the same two helpers, and
    `dumps_agree` must accept that against `$tmp/dis.words` too - so the three oracles agree and the disassembler
    cannot agree with the input while disagreeing with the source the project already trusts. Limb 4: two `dis` runs
    on the same input are byte-identical (`cmp`).

    `asm.dis.two-word-form` - the word dump holds at least two more lines than the emitted source holds instruction
    lines, where an instruction line is an indented upper-case mnemonic line **with or without an operand**
    (operand-less rows such as `HLT` and `DIS` are instruction lines and must be counted) and an `ORG` directive
    line is not one. The emitter writes no labels, so the count is exact on its own output: sixteen instruction
    lines against 22 words on the boot stub. The margin of two is deliberate - a miscount of one on either side
    cannot flip the verdict - and the corpus carries six operand rows, so the margin is a real observation rather
    than a coincidence.

    `asm.dis.immediate` - the emitted source contains an immediate form (the `MVII` mnemonic followed by `#`), and
    the committed twin's source does too, so the guard is about the corpus rather than about one emitter's
    coincidence. The twin's instruction-line count is **not** used for the two-word-form guard, because the twin is
    written with labels at column one and a leading-space count would undercount it.

    `asm.dis.words-nonvacuous` - the dump holds more than zero lines, the emitted source holds more than zero
    instruction lines, and the emitted source's distinct mnemonics number at least three: a `DECLE`-everything
    emitter round-trips perfectly and would pass every other limb, so this is the count that catches it.

    `asm.dis.deterministic` - two `dis` runs into two paths are byte-identical, which is the `asm.repeat` shape.

    `asm.judge.dis-constant-mnemonic` - the stand-in, committed as a case: every instruction line of the emitted
    source is replaced by the whole line `DECLE $0000` (the `asm.judge.mutated-twin` `sed` idiom, applied to the
    emitter's own output, with the `ORG` lines left alone), the result is reassembled with `twin_words`, and
    `dumps_agree` must **reject** it with a diff. The replacement has to be a complete line and not a mnemonic
    swap: keeping the operand text produces `DECLE #$0001, R0` and `DECLE R0`, which `ivs_asm` refuses as
    `asm-operand-kind`, and `DECLE $1010`, which it refuses as `asm-decle-range` (a data word is at most `03FF`) -
    so a mnemonic-only substitution never assembles and the case would fail on a correct implementation for the
    assembler's reason instead of the word difference. `DECLE $0000` assembles (measured this session: rc 0, 16
    words against the listing's 22, dump differing) and produces the failure the criterion names. If `dumps_agree`
    accepts the stand-in the case records `judge-vacuous` and fails, and if the assembler refuses it the case
    records `judge-wrong-reason` and fails - a refusal is not the comparison failing. Its declared finding is
    exactly one: the word difference.
