    (a) `tools/inspect/inspect_dis.c`, one new translation unit, added to `IVS_INSPECT_SOURCES` in
    `tools/inspect/CMakeLists.txt` (the `ivs-inspect-sources.txt` writer follows the list automatically, so no other
    build edit is needed and a tracked source outside the list would be a `c-build` finding).

    The command is `dis <listing> --out <file.asm>`, with the same exit statuses and the same output ladder
    `18-02` established (tree refusal, then exists, then exclusive create, then a short write removing what it
    created). Reading a listing: skip blank lines and `#` lines, copying every leading `#` line verbatim into the
    output first, in order, because `ivs_asm` requires the `# window:` line and the page says the header is copied.
    Then each word line is split on whitespace. The first field is the address and the second the word; the `BITS`
    column is space-separated into a variable number of groups, so the row is found by consuming every following
    field whose characters are all `0` or `1` and taking the next one - the row is either `-` or an upper-case row
    id, and nothing else in the line can be mistaken for it. A line whose row is `-` is an operand word of the
    instruction above it and is not emitted as its own line; the rest of the line after the row is the `ASM` text.

    The mnemonic is the row field verbatim, lower-cased only for the refusal token's detail - it is the listing's
    own leaf row id, so no mnemonic table exists. A row the emitter does not know is refused with
    `inspect-dis-row`, naming the row and the address, **before** the output is created, so a failed `dis` leaves no
    file. The operand text is the asm field cut at the branch and jump annotation (the two spaces, arrow, two
    spaces sequence the listing uses between the operand and its target) and then cut at the first run of two or
    more spaces, which is how the listing separates an operand from its trailing note; the result is trimmed of
    trailing spaces and written after the mnemonic on an eight-column indent. Where the address is not the previous
    line's address plus the previous instruction's word count, emit an `ORG` directive with the address in four
    upper-case hex digits preceded by `$`, so a gap or a jump in the listing is preserved rather than silently
    packed. Record in the file's header comment that the mnemonic is the listing's own row and the operand text its
    own asm column, that the only thing this file knows is how to cut the annotation and when to emit `ORG`, and
    that the round trip through `ivs_asm` is what proves the cut - so a later listing with a different annotation
    fails loudly instead of disassembling wrongly.

    If the cut proves not deterministic on the corpus during this task, fall back to deriving the operand from the
    `BITS` field groups plus the following `-` rows' words (the research's option 1) and record the fallback as a
    deviation with the reason; do not weaken the refusal, the `ORG` rule, or any of the four guards below.

    (b) `tests/CMakeLists.txt`: `"$<TARGET_FILE:ivs_inspect>"` becomes the fourth argument of the `asm`

    `asm.dis.roundtrip-boot-stub` - four limbs. Limb 1: a copy of the boot-stub listing in `$tmp` whose first word
    line's row field is replaced with an unknown row is refused with `inspect-dis-row`, exit 1, one stderr line, and
    no output file. Limb 2: the real listing is disassembled to `$tmp/dis.asm` and `twin_words` assembles it to
    `$tmp/dis.listing` and dumps its words to `$tmp/dis.words`; the input listing's words are dumped to
    `$tmp/hand.words` with `ivs_pack --dump-words`; `dumps_agree` must accept. Limb 3: the committed twin
    `tests/asm/twins/boot-stub.asm` is assembled and dumped to `$tmp/twin.words` with the same two helpers, and
    `dumps_agree` must accept that against `$tmp/dis.words` too - so the three oracles agree and the disassembler
    cannot agree with the input while disagreeing with the source the project already trusts. Limb 4: two `dis` runs
    on the same input are byte-identical (`cmp`).

    `asm.dis.two-word-form` - the word dump holds at least two more lines than the emitted source holds instruction
    lines, where an instruction line is an indented upper-case mnemonic line and an `ORG` directive line is not one
    (the emitter writes no labels, so this count is exact on its own output). The margin of two is deliberate: a
    miscount of one on either side cannot flip the verdict, and the boot stub's corpus carries six operand rows, so
    the margin is a real observation rather than a coincidence.

    `asm.dis.immediate` - the emitted source contains an immediate form (the `MVII` mnemonic followed by `#`), and
    the committed twin's source does too, so the guard is about the corpus rather than about one emitter's
    coincidence. The twin's instruction-line count is **not** used for the two-word-form guard, because the twin is
    written with labels at column one and a leading-space count would undercount it.

    `asm.dis.words-nonvacuous` - the dump holds more than zero lines, the emitted source holds more than zero
    instruction lines, and the emitted source's distinct mnemonics number at least three: a `DECLE`-everything
    emitter round-trips perfectly and would pass every other limb, so this is the count that catches it.

    `asm.dis.deterministic` - two `dis` runs into two paths are byte-identical, which is the `asm.repeat` shape.

    `asm.judge.dis-constant-mnemonic` - the stand-in, committed as a case: every instruction line of the emitted
    source is replaced by one mnemonic (the `asm.judge.mutated-twin` `sed` idiom, applied to the emitter's own
    output), the result is reassembled with `twin_words`, and `dumps_agree` must **reject** it with a diff; if it
    accepts, the case records `judge-vacuous` and fails, and if it rejects for a reason other than the word
    difference the case records `judge-wrong-reason` and fails. Its declared finding is exactly one: the word
    difference.
