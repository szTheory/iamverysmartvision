## 5. Tech debt and deferred items

Aggregated from `.planning/STATE.md` "Deferred Items", `08-ACCEPTED-DEBT.md`, the integration checker's five warnings, and the Nyquist discovery. Full list in the frontmatter.

**Character of the debt:** it is recorded, accepted and dated, not discovered now. It falls into four kinds:
1. **Gate hardening** (Phase 1, Phase 3, plus integration W2): low severity; each item would make an existing check harder to pass vacuously.
2. **Evidence limits** (no tier-1 PSG sheet, one community STIC lineage, one model family, unmeasured hardware, D11 not performed): these are the project's honesty budget. They cap claims at `provisional` and are the reason no claim uses the `measured-hardware` tier.
3. **Deferred capability** (snapshot file options, 192-line video, libFuzzer in CI, SHA-256 optimization, an idle-host baseline): each has a stated trigger.
4. **Bookkeeping** (seven draft VALIDATION.md files, one stale comment, two missing bench commands in `docs/runner.md`, the rulesets not applied).

**Integration W1 is the most substantive item**: 17 requirements (FND-01..07, CPU-01..05, MEM-01..05) have named faults that run in every gate (`faults=235/235`) but no lines in `data/expected/important-gates.ids`, so they lack the registered "cannot pass vacuously" evidence the later phases have. It affects the durability of the evidence, not the current wiring or any claim's tier.
