## 3.1 One rights row: `inspection-output`

`data/rights/inspection-output.json` carries `disposition: owner-local-only`,
`source: null`, `taken: "nothing"`, and the tokens `trace-file`,
`disassembly-dump`, `inspection-dump`. The item is *an access trace or a
disassembly of operator content*.

`[OBS]` None of the three spellings occurs in `core/src/`, `runner/`, `tools/`,
`host/` or the pinned pages, so `rights-pinned.ids` stays at its four pairs and no
pin is added: a pin is a deliberate diff, never a tidy-up. "Nothing is taken"
means no image byte, no digest and no tracked path.

One commit moves the row, `data/expected/rights.ids`, the `docs/RIGHTS.md` table
row and the manifest id that reads it. **Reversal:** an output that must be
committed becomes a fixture question with its own manifest.

## 3.2 The naming limb widens by one page, by zero tokens

`docs/inspection.md` joins `rights_scan_naming`'s page list as the **eighth**
exact page, in the commit that creates it — the surface a person reads is closed,
never a glob. The frozen page must therefore never spell a token: it names the
outputs with the ordinary words *trace* and *disassembly* and with the tool's own
`inspect-` family, which are not rights tokens.

`ivst` is an **extension, not a token**: tokens are hyphenated prose spellings and
extensions are refused by name. No new `binary-ext.txt` control is needed; the
existing `files-unlisted-binary-*` controls prove the mechanism. **Reversal:** a
page that must name a token is a pin, priced as a diff.

## 3.3 What `docs/inspection.md` states, and what it never contains

Frozen before any code, with ancestry proved by `git merge-base --is-ancestor`,
the document states: one record per line and its field list; the cycle stamp is
the machine's own tick count, the same time base as the report's `step.*` lines;
records are cycle-monotonic and non-decreasing with a stated tie order; a bound on
records, and a truncated trace states its bound; the command surface is scripted,
so the tool is headless-verifiable; the trace is read through the side-effect-free
peek path and never alters the run; and it is **not** an observation of hardware
and never a claim artifact.

It **never** contains: a content digest, any path, any image name, any pixel, any
audio byte, any hash of an operator file, or any container byte.

## 3.4 The output is refused inside the work tree; token `inspect-output-tree`

The tool refuses an output path inside the work tree except under the ignored
`refs/` (the `flatwrap-output-tree` precedent), refuses an existing file, and
refuses a path whose extension is not `ivst`. Its whole token set is pinned
append-only in `data/expected/inspect-refusals.ids`, one case per token in the
existing tool suite.

`ivst` joins `.gitignore` and `tools/check/binary-ext.txt` in the same commit (the
`ivsc`/`ppm`/`ivsn` precedent: one list feeds the tree, the archive and the
hygiene rule), and the claim-artifact predicate gains `[.]ivst$` in the same
commit.

**Consequence: no trace or disassembly is ever committed, whatever its content** —
project-authored or operator — and CI writes one only inside a `mktemp` tree.
**Reversal:** a text-integrity need for `.ivst` moves the rule to a dedicated path
refusal with its own control.

## 3.5 Build-only posture: `tools/inspect/`, target `ivs_inspect`

Its own target, no install rule, never installed, outside the eleven-path prefix.
Its source ships in the source archive like `tools/flatwrap`. One line joins the
`c-build` module list (`tools/inspect/*.c` into `ivs-inspect-sources.txt`), which
makes an unlisted source a `c-build-unlisted-source` failure for free.

The install archive refuses it three ways with **no new id**: the eleven-path
inventory equality (`pkg-install`), `release-assets-extra-member`, and
`release-assets-binary-member` for any `ivst` member. `host-so-absent` already
proves the inventory mechanism can fail.

## 3.6 The release-decision line, and the host-shim correction

`[OBS]` `host/ivs_retro_shim.c` is tracked, so the source archive *does* carry the
shim's source. "No host shim ships" is therefore narrower than the evidence. The
correction is **appended** to `RELEASE-OPS.md`, never a rewrite of the existing
line:

> the release ships the static package (the eleven pinned paths) and the source
> archive, which carries the source of the build-only tools and of the build-only
> host shim; no shared object, no built host shim, no built inspection tool, no
> trace or disassembly output, no content
