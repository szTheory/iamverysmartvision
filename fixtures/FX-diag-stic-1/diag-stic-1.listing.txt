# id: ivs-diag-stic-1
# kind: cart
# profile: intv-2609-ntsc-family-p1
# window: 5000-5084
# label: ivs-diag-stic-1, the third project-authored diagnostic (display enable, graphics RAM, BACKTAB, both card modes)
# entry: 5000
# stack: 0340
#
# Project-authored diagnostic (D-20), MIT like the rest of the repository. tools/pack builds it
# into one IVSC v1 segment at 5000 (133 words) in the build tree; no image is committed. It is
# entered through the project boot stub (fixtures/FX-boot-stub/boot-stub.listing.txt, contract 1,
# unchanged), which jumps to 5000 with R6 = 0340 and interrupts disabled; the program has no
# interrupt service routine, calls no EXEC routine and reads no graphics ROM, so the display is
# not sustained and exactly one picture, frame 0, exists. Both numbers are project conventions
# with no hardware or first-party source (discrepancy C68), so the program sets every register it
# uses before using it. The program, the cycle budget, the six explicit words and the card patterns
# are derived in docs/video/diag-stic-1-derivation.md (committed before this listing existed); the
# expected frames are data/video/frames/F-D1.frame (Foreground/Background) and F-D2.frame (Color
# Stack), and the expected state is the header of data/golden/diag-stic-fgbg-pass.expect.
#
# Sections:
#   a  5000-500B  read port 0 (01FE), keep the low byte, record it at 02F1, and select Color Stack
#                 mode (a read of 0021) only when the low byte is not FF (a key is closed). One
#                 branch, so one image serves both modes (the scenario supplies KEY_1 at tick 0).
#   b  500C-500D  the display-enable strobe (a store to 0020; the value written is ignored).
#   c1 500E-501B  the four color stack registers 0028..002B get 6, A, 3, D (used by Color Stack
#                 mode only; written in both modes).
#   c2 501C-502A  copy the 32 bytes of the pattern table at 5065 to graphics RAM 3800..381F
#                 (cards 0 to 3) through R4 (source) and R5 (destination).
#   d  502B-5033  fill the 240 BACKTAB words 0200..02EF with 0000.
#   e  5034-5057  six explicit card words, each a 14-bit value, so each is SDBD, MVII, MVO:
#                 02A3 = 2A01, 02A4 = 0E0A, 02A5 = 1A13, 02A6 = 381C, 02DC = 2C1D, 02EF = 1C0F.
#   f  5058-505C  counted delay (R1 = 900 = 0384) so the stop comes between the first and the
#                 second frame end, with display on and with the strobe removed.
#   g  505D-5064  the end marker 03C5 written last at 02F0, then HLT and three TSTR R0 followers
#                 (docs/diagnostics.md, "Endings need a follower").
#   data 5065-5084  the 32 pattern bytes, one decle each (the 10-bit word holds an 8-bit byte):
#                 card 0 stripes FF 00 FF 00 FF 00 FF 00; card 1 box FF 81 81 81 81 81 81 FF;
#                 card 2 diagonal 80 40 20 10 08 04 02 01; card 3 checker AA 55 AA 55 AA 55 AA 55.
#                 Project-authored geometric shapes only; no letter shape and no pattern recalled
#                 from a real graphics ROM. The listing checker decodes every word as a program
#                 word, so each table line carries the row of the decle it encodes, and the three
#                 decles 04, 02, 01 of card 2 are the one three-decle jump the checker sees in the
#                 table (printed with its recomputed target, never executed: the table lies behind
#                 the three followers).
#
# Line grammar (D-26): ADDR HEX4 BITS ROW ASM, as in the boot stub listing. ROW is the leaf row of
# data/cp1610/opcode-families.json or - for an operand word. Every branch line carries `-> ADDR`
# (docs/diagnostics.md, "Branch targets"). Every immediate above 03FF is written SDBD, MVII with
# its low byte then its high byte (the listing-sdbd rule of docs/diagnostics.md).
#
# Derivation of the encodings (hand-assembled; no assembler; nothing copied from another
# implementation; "pdf N" is a page of the GI CP-1600 Microprocessor Users Manual,
# SRC-gi-cp1600-um-1975; register numbers are 3-bit fields, R0 = 000 ... R7 = 111):
#   MVI   1010 000 DDD then the address word (direct table, pdf 55): R0 gives 0280.
#   MVO   1001 000 SSS then the address word (direct table, pdf 55): R0 gives 0240.
#   MVII  1010 111 DDD then the immediate word (immediate table, pdf 57): R0 02B8, R1 02B9,
#         R4 02BC, R5 02BD. After SDBD the operand is two decles, low byte then high byte (SDBD
#         table, pdf 58).
#   SDBD  0000 000 001 (control table, pdf 56; Fig 3.3.4, pdf 51): 0001. It applies to the next
#         instruction only.
#   ANDI  1110 111 DDD (immediate table, pdf 57): R0 gives 03B8.
#   CMPI  1101 111 SSS (immediate table, pdf 57): R0 gives 0378; it sets Z when the register
#         equals the immediate.
#   CLRR  0111 DDD DDD (register-register table, pdf 53): R0 gives 01C0. DECR 0000 010 DDD: R1 is
#         0011. TSTR 0010 SSS SSS: R0 is 0080. HLT 0000 000 000.
#   MVO@  1001 MMM SSS with MMM = 100 for R4 and 101 for R5, post-incremented (indirect table,
#         pdf 55; Fig 3.2.1, pdf 46): MVO@ R0,R4 is 0260, MVO@ R0,R5 is 0268.
#   MVI@  1010 MMM DDD (indirect table, pdf 55): MVI@ R4,R0 is 1010 100 000 = 02A0, R4 post-
#         incremented.
#   BZE   1000 S0 0100 and BNZE 1000 S0 1100, then the displacement word; S = 0 forward: PC + 2
#         plus the displacement; S = 1 backward: PC + 1 minus the displacement (branch table,
#         pdf 54): BZE forward 0204, BNZE backward 022C.
# Branch arithmetic:
#   BZE at 5008 (skip the mode select): PC + 2 = 500A, target 500C = 500A + 0002, so d = 0002.
#   BNZE at 5029 (copy loop): PC + 1 = 502A, 502A - d = 5026, so d = 0004.
#   BNZE at 5032 (fill loop): PC + 1 = 5033, 5033 - d = 5030, so d = 0003.
#   BNZE at 505B (delay loop): PC + 1 = 505C, 505C - d = 505A, so d = 0002.
#   The jump decode of the table at 507A: second decle 0002, bits 7..2 = 000000, third decle 0001,
#   target 0001.
# Cycles (regression information; the branch counts are policy C29; the full budget with the
# bus windows is section (c) of docs/video/diag-stic-1-derivation.md): the program runs about
# 20,716 cycles with no bus window (fill loop 5,758, delay 13,506), the HLT unit starting at tick
# 82,864 with the display off and between 87,388 and 88,948 ticks with the display on. No
# assertion depends on these numbers; only the margins to the frame ends 59,736 and 119,472 are
# a requirement of the design.
