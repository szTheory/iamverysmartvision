# label: ivs-diag-ctrl-psg-1, the second project-authored diagnostic (controller reads and PSG register writes)
# entry: 5000
# stack: 0340
#
# Project-authored diagnostic (D-24), MIT like the rest of the repository. tools/pack builds it
# into one IVSC v1 segment at 5000 (89 words) in the build tree; no image is committed. It is
# entered through the project boot stub (fixtures/FX-boot-stub/boot-stub.listing.txt, contract 1),
# which jumps to 5000 with R6 = 0340; both numbers are project conventions with no hardware or
# first-party source (discrepancy C68), so the program sets every other register it uses before
# using it. It uses no SDBD, no interrupt, and no STIC, GROM or graphics RAM address; every
# operand address is below 0400, so each address word is one decle; the three PSG-facing paths are
# the 11 register writes of S1, the two port reads of S2 and the system RAM stores of S2 and S3.
# The expected values are derived in docs/input/diag-ctrl-psg-1-derivation.md (committed before
# this listing existed; section (g) there records the one correction made while assembling) and
# in the header of data/golden/diag-ctrl-psg-pass.expect.
#
# Sections:
#   S1 PSG     5000-502B  eleven MVII #value,R0 / MVO R0,$addr pairs: the PSG registers 0, 4, 8, 11,
#                         1, 5, 12, 9, 3, 7, 10 (addresses 01F0, 01F4, 01F8, 01FB, 01F1, 01F5,
#                         01FC, 01F9, 01F3, 01F7, 01FA) get 0023, 0001, 003E, 000F, 0080, 0000,
#                         0008, 0010, 0064, 0000, 000A. The mixer value 003E keeps bits 6 and 7
#                         clear: both ports stay inputs, so a read of 01FE or 01FF returns the pins.
#   S2 poll    502C-504B  R1 = R2 = 0100 (previous values no masked read can equal), R4 = 0210 and
#                         R5 = 0220 (store pointers, auto-incremented by MVO@), R3 = 0008 (port 0
#                         values still to store). Loop at 5036: read 01FE, keep the low byte, and
#                         when it differs from the previous value store it at [R4] and count it
#                         down; the same for 01FF with R2 and R5 (no count); TSTR R3 and back
#                         while eight port 0 values are not yet stored.
#   S3 delay   504C-5058  R0 = 0078 counted down (120 iterations of DECR and a taken BNZE), then
#                         the end marker 03C5 written last at 020F, then HLT and three TSTR R0
#                         followers (docs/diagnostics.md, "Endings need a follower").
#
# Line grammar (D-26): ADDR HEX4 BITS ROW ASM, as in the boot stub listing. ROW is the leaf row of
# data/cp1610/opcode-families.json or - for an operand word. Every branch line carries `-> ADDR`
# (docs/diagnostics.md, "Branch targets").
#
# Derivation of the encodings (hand-assembled; no assembler; nothing copied from another
# implementation; "pdf N" is a page of the GI CP-1600 Microprocessor Users Manual,
# SRC-gi-cp1600-um-1975; register numbers are 3-bit fields, R0 = 000 ... R7 = 111):
#   MVII  1010 111 DDD, then the immediate word (immediate table, pdf 57): R0 02B8, R1 02B9,
#         R2 02BA, R3 02BB, R4 02BC, R5 02BD.
#   MVO   1001 000 SSS, then the address word (direct table, pdf 55): R0 gives 0240.
#   MVI   1010 000 DDD, then the address word (direct table, pdf 55): R0 gives 0280.
#   ANDI  1110 111 DDD, then the immediate word (immediate table, pdf 57): R0 gives 03B8; the CP-1610
#         has no OR instruction (the mutant ANDI-TO-MVII changes this first decle to 02B8).
#   CMPR  0101 SSS DDD (register-register table, pdf 53): CMPR R1,R0 is 0101 001 000 = 0148 and
#         CMPR R2,R0 is 0101 010 000 = 0150; it writes S, Z, C and OV, and Z = 1 when the two
#         registers are equal.
#   MOVR  0010 SSS DDD: MOVR R0,R1 is 0010 000 001 = 0081, MOVR R0,R2 is 0082; TSTR 0010 SSS SSS:
#         TSTR R3 is 0010 011 011 = 009B and TSTR R0 is 0080 (pdf 53); DECR 0000 010 DDD: DECR R3 is
#         0013, DECR R0 is 0010 (pdf 53); HLT 0000 000 000 (control table, pdf 56).
#   MVO@  1001 MMM SSS with MMM = 100 for R4 and 101 for R5, post-incremented (indirect table,
#         pdf 55; Fig. 3.2.1, pdf 46): MVO@ R0,R4 is 1001 100 000 = 0260, MVO@ R0,R5 is 0268. Only
#         R4 and R5 increment; R1 to R3 do not (the derivation, section (g)).
#   BZE   1000 S0 0100 and BNZE 1000 S0 1100, then the displacement word; S = 0 forward: PC + 2 plus
#         the displacement; S = 1 backward: PC + 2 plus the one's complement of the displacement
#         (branch table, pdf 54): BZE forward 0204, BNZE backward 022C.
# Branch arithmetic:
#   BZE at 503B (skip port 0 store): PC + 2 = 503D, target 5040 = 503D + 0003, so d = 0003.
#   BZE at 5045 (skip port 1 store): PC + 2 = 5047, target 5049 = 5047 + 0002, so d = 0002.
#   BNZE at 504A (back to the poll): PC + 2 = 504C, S = 1: 504C - d - 1 = 5036, so d = 0015.
#   BNZE at 504F (delay loop): PC + 2 = 5051, 5051 - d - 1 = 504E, so d = 0002.
# Cycles (regression information, V-07; the branch counts are policy C29): one poll loop without a
# store is MVI 10 + ANDI 8 + CMPR 6 + taken BZE 9, twice, plus TSTR 6 + taken BNZE 9 = 81 CPU
# cycles = 324 ticks; the delay is 120 x DECR 6 + 119 x taken 9 + 7 = 1798 cycles = about 7,200
# ticks. No assertion depends on these numbers.
