# Literal memory map of profile intv-2609-ntsc-family-p1 (D-21; plan 03-05).
#
# Claim tier: source-expectation. This file is a transcription of the source readings recorded
# for phase 3 (GI 1980 data catalog, the 2609 technical overview, one community wiki revision).
# A pass of the memmap gate step shows that the runtime decode is consistent with this
# transcription, not that the console behaves this way. Most address rows rest on one tier-4
# community lineage; the tier-1 rows are marked tier1-primary-doc.
#
# Independence rule: this file is written from the sources only. It is never derived from,
# generated from or edited to match the profile descriptors it judges, and it names no profile
# field. Where a source and the profile differ, this file keeps the source reading (D-18) and
# the profile is the side that changes. Emulator source code is never a source for a row;
# a row tagged tier5-emulator-hint, or citing a tier-5 source, is refused by the gate.
#
# Row grammar (one row per line, single spaces, columns in this order):
#   <R|W> <LO>-<HI> <device> w=<bits> impl=<real|stub|none> mirror=<words|-> gate=<name|-> src=<SRC-id>@<locator> tag=<tag> [conf=C<n>] [x=<name>]
#   R, W       read view and write view; each view tiles 0000-FFFF exactly once, gaps are
#              explicit undriven rows.
#   LO, HI     inclusive word addresses, four uppercase hex digits, LO <= HI, rows ascending.
#   device     stic scratchpad psg sysram exec grom gram cart undriven
#   w          driven read bits of the row: 10 for decle ROM, 8 for GROM and 8-bit RAM and the
#              PSG registers it covers, 4 to 6 for the narrower PSG registers, 16 for system RAM,
#              0 for stub devices and undriven space. In the write view w is the width a store
#              keeps when read back (0 where a store is dropped).
#   impl       real (behaviour modelled), stub (decoded and named, reads give the undriven
#              value, writes are dropped; no row uses it since plan 06-06), none (undriven rows only).
#   mirror     words of the backing or register file the row reaches, when that backing is
#              smaller than the row or is shared with another row (an alias); - when the row is
#              the sole full-extent home of its device. Undriven rows carry -.
#   gate       stic-regs or gmem (an access window that the machine can close); - for none.
#   src        a source id of data/sources.json and a locator in [A-Za-z0-9._,-]: pdf-<n> is a
#              pdf page of the GI 1980 catalog (pdf = printed page + 181, so pdf-194 is printed
#              5-13, pdf-197 is 5-16, pdf-199 is 5-18, pdf-202 is 5-21); Memory_Map.oldid-14847
#              is revision 14847 of the community wiki's memory map page. src=none is allowed
#              only on undriven rows, which must then carry tag=unknown-default-chosen and conf.
#   tag        a source-authority tag of data/tiers.json (never tier5-emulator-hint).
#   conf       a discrepancy id of data/discrepancies.json that qualifies the row.
#   x          optional last column, a declared exception row whose read-back is not the value a
#              store kept (plan 05-04): x=reads-zero (the read mask of the register is 0: a store
#              keeps w bits that a read never returns, C75; an impl=real row with w=0 needs it),
#              x=pins (a port register whose read follows the direction bit and the pins, plan
#              05-05: the read view has width 0, since the byte read does not depend on the word
#              stored, and an impl=real row with w=0 accepts it; the write view keeps its 8 bits)
#              or x=strobe (plan 06-06: the registers of the row store nothing, a store keeps no
#              bit, and the access may have a machine-level effect instead: the two strobe
#              registers $0020 and $0021 and the reserved registers around them; an impl=real row
#              with w=0 accepts it). The STIC read view rows whose read mask is 0 (write-only
#              registers, strobes, reserved) read FFFF and are marked x=reads-zero, and so are the
#              write rows of the stored write-only registers, whose w bits a read never returns.
#              The behavioural width probe of an exception row observes the store in the memory
#              system's register storage, not through a bus read; the named rows are $01FA, $01FE
#              and $01FF and every STIC write-view address ($0000-$003F and the three aliases).
#              An x=pins row reads the idle byte 00FF after power-on whatever was
#              stored (ports in input mode, no pin held low; data/psg vectors family port and
#              the input suite cover the pins and the direction).
#
# Source notes per row group (labels: OBS read in the source, INF inference):
#   sysram 0200-035F, 16 bits: RA-3-9600 is 352 x 16 at words 512-863, all 16 bits stored
#     (GI 1980 printed 5-18) [OBS].
#   exec 10 bits: RO-3-9502 outputs 10 data bits and drives the top six bits to zero
#     (printed 5-13) [OBS]; the placement at 1000-1FFF is the community reading (C20).
#   grom 3000-37FF, 8 bits: RO-3-9503 is 2048 x 8 with the upper eight bits driven to zero and
#     sits at 12288-14335 in the CPU-time view (printed 5-16) [OBS].
#   gram 3800-3FFF: printed 5-16 puts the external graphics memory at 14336-16383 [OBS]; decoding
#     the whole 2K window onto 512 words (two 256 x 8 RAMs, 2609 overview) is [INF] (C21).
#   cart 4000-FFFF, 10 bits: RO-3-9504 drives the upper six bits to zero (printed 5-21) [OBS];
#     the span itself is a chosen default narrower than the community list (C62).
#   stic, scratchpad addresses and every alias: community wiki only (C11, C21, C60, C61).
#   psg 01F0-01FF, plan 05-04: sixteen registers, one word per address, only the low byte driven,
#     the upper byte reads 0 (C64); the community wiki page PSG-oldid-14940 gives the addresses, the
#     roles and the data-bit columns, the 1980 catalog the register widths (C70). Rows are split
#     where the stored width changes: 8 bits for the fine tone periods, the envelope period, the
#     mixer and the two ports, 4 for the coarse tone periods and the envelope shape, 5 for the noise
#     period, 6 for the amplitudes. The shape register reads 0 whatever was stored (C75), so its read
#     row has w=0 and its write row w=4, both marked x=reads-zero; the two port registers are marked
#     x=pins (plan 05-05): their read row has w=0 (the byte read follows the pins), their write row w=8. The register-address literal data/psg carries the masks per register.
#   stic 0000-003F, plan 06-06: the five STIC regions are the real device (impl=real), the rows split
#     where the register width or the read-back model changes, exactly as the independent register
#     literal data/stic (sixty-four rows) states: the stored registers keep 11, 12 or 14 bits (mob x,
#     y and attribute), 4 (color stack and border), 3 and 2 (delays and border extension) and read
#     FFFF (the undriven fill, C81); the eight collision registers keep and read 10 bits and read FC00
#     OR the stored bits (read mask 03FF, fill FFFF); the two strobe registers and the reserved
#     registers keep nothing. The read alias at 0040-007F mirrors the register file, so it splits
#     like the home rows; the three write aliases mirror the write rows. The merged rows are the ones
#     the dump probe produces (adjacent addresses with the same structure are one row).
#   alias gates: an alias reaches the same STIC registers or graphics RAM as its home row, so
#     it carries the home row's gate (stic-regs or gmem) [INF from the wiki's alias wording].
#   scratchpad: one 256 x 8 RAM per the 2609 overview, 240 words decoded at 0100-01EF.
#   undriven: reads give the pull-up value (C5); writes go nowhere.
