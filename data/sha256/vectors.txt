#   <id> <message-spec> <sha256-hex>
# The test id is machine.sha256.<id> (suite machine, family sha256). Message specs:
#   lit:<text>          the bytes of <text>, which holds only letters and digits (may be empty)
#   pat:<length>        <length> bytes, byte i is character (i mod 62) of the 62-character
#                       alphabet A..Z a..z 0..9 (so every pattern message is a prefix of a
#                       longer one)
#   rep:<char>:<count>  <char> (a letter or digit) repeated <count> times (count 1..1000000)
# Provenance: every digest was typed in at authoring time from `cmake -E sha256sum` over a
# scratch file holding the message (never from the code under test). fips-abc, fips-448 and
# fips-million-a also equal the SHA-256 example digests NIST publishes for FIPS 180-4.
# fips-896 (the 896-bit message of the NIST SHA-384/512 examples) and fips-empty rest on the
# cmake digests alone. cmake/IvsShaVectors.cmake re-derives every line with
# CMake's string(SHA256) at build time and stops the build on any mismatch, so a typo here
# cannot pass.
