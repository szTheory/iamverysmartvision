# tests/asm/pairs.txt: the flat corpus behind the second outside check of the ivs_asm encoding table
# (plan 07-04, D-18, T1). Run by the suite asm as: ivs_asm --pairs tests/asm/pairs.txt
# Line form: CLASS ADDR WORDS ASM. CLASS is the row family (the suite asm reports one result per class),
# ADDR the address the statements are assembled at (four hex digits), WORDS the expected decles as
# comma-separated four-digit hex, ASM one or more statements separated by a semicolon and a blank.
# Provenance: the lines below the first marker were copied once, on 2026-11-13, from the asm and program
# fields of data/cp1610/vectors/*.json (the address is init.r[7] of each vector), keeping the vector order
# of the files in name order. Those vectors are hand-derived from the manual pages and read a second time
# blind (docs/cp1610/reference-notes.md, "Vector second reading"); ivs_asm never read them and no line
# below was produced by it, so each pair is an expected value the tool did not write. A line is copied when
# its asm text is plain statements of the dialect and every program word is at most 03FF. The only edit is
# the operand words of an SDBD immediate pair, whose upper bits the manual marks Not Used (pdf 58) and the
# vectors fill with filler: they are written here masked to their low byte. Left out on purpose, because the
# dialect refuses the spelling or the vector exercises the core: a wraparound branch or a program that wraps
# the address space, SDBD alone or before a row that is not an SDBD target, MVO@ with the source equal to
# the pointer register 4 to 7 (pdf 55), NOPP with a displacement word, an immediate above 03FF without SDBD,
# and MVOI (no spelling).
# The vectors are pinned by the tests-vectors-digest token of the tests-inventory step: a deliberate vector
# change is a visible diff, and this file is mirrored by hand then (there is no JSON parse at test time).
# Lines under the second marker are hand cases derived from docs/cp1610/reference-notes.md: XORI is
# 1111 111 DDD (pdf 57), ANDI 1110 111 DDD, NOPP 1000 S0 1000 with S = 0 and a displacement word 0000
# (pdf 54), SDBD 0000 000 001, and under SDBD the immediate is a low byte word then a high byte word.
