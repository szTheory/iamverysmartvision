## (a) Program specification

<!-- blind-spec-begin -->

The program `ivs-demo-lamp-tone-1` ("Lamp Tone") is an original cartridge program entered through the project boot stub, contract 2 (cartridge reset entry `$5000`, cartridge interrupt entry `$5004`, the stub hands every interrupt to `$5004` with the interrupt system disabled), with the zero graphics ROM and profile `intv-2609-ntsc-family-p1`. It makes two rows of eight lamps follow the two controller ports and gives each port one PSG voice. It has no text, no graphics ROM read, no EXEC call, no data table and no moving object, and it never halts.

**A1 Ports.** The scenario words `c0` and `c1` drive the two ports that a guest reads at `$01FE` (`c0`) and `$01FF` (`c1`); the program never names a player. The byte of a port is the low eight bits of the word read; a pressed control clears bits (the controller literal gives each control's byte and the rule that a combination clears the union of the bits), so an idle port reads `FF`.

**A2 Lamps.** Each port has a row of eight lamps. Lamp i, i = 0 to 7 from left to right, shows bit 7 minus i of the port byte and is lit when that bit reads 0 (a cleared bit lights its lamp; nothing is decoded, so an ambiguous combination of controls is shown as the union of its bits). A lit lamp is color index 2 and an unlit lamp is color index 1.

**A3 Display.** The display uses Foreground/Background mode with one project-authored graphics RAM card, card 0, a solid block (its eight pattern bytes `$3800` to `$3807` are all `FF`, so every pixel of the card is foreground). The lamp rows are BACKTAB cells: port 0 occupies row 4, columns 6 to 13, that is addresses `$0256` to `$025D` (lamp i at `$0256` plus i); port 1 occupies row 7, columns 6 to 13, addresses `$0292` to `$0299` (lamp i at `$0292` plus i). An unlit lamp word is `$0801` (graphics RAM card 0, foreground 1) and a lit lamp word is `$0802` (foreground 2); the background field of both is 0. All 16 lamp words are written in every interrupt service routine, whether or not a port changed. Every other BACKTAB word is `$0000` (graphics ROM card 0, foreground 0, background 0; the zero ROM has no image, so such a cell shows color index 0 everywhere). In the delivered plane (159 x 96 positions) lamp i of port 0 covers x = 48 + 8 i to 55 + 8 i, y = 32 to 39, and lamp i of port 1 covers x = 48 + 8 i to 55 + 8 i, y = 56 to 63; the declared lamp rectangles are x = 48 to 111 with y = 32 to 39 (port 0) and y = 56 to 63 (port 1). The border color and the color stack stay at their power-on values (0).

**A4 Memory map of the program.** `$02F0` init marker, `$03C5` once initialization is done; `$02F1` frame counter; `$02F2` port 0 last byte; `$02F3` port 0 change counter; `$02F4` port 1 last byte; `$02F5` port 1 change counter; `$02F6` and `$02F7` pending amplitude words of port 0 and port 1 (`0000` nothing pending, otherwise the amplitude to write plus one: `0001` means amplitude 0 and `0010` means amplitude 15); `$0340` and up the stack (one word is used and discarded per interrupt). Every variable is a 16-bit word. The BACKTAB cells are `$0200` to `$02EF`. A last-byte word holds the byte with the upper eight bits zero (for example `007E`).

**A5 Initialization (frame 0), in this order.** (1) The graphics RAM card first: write `FF` to `$3800` to `$3807`. (2) Clear `$0200` to `$02FF` to `0000` (the BACKTAB and the variable area). (3) Store `00FF` at `$02F2` and at `$02F4`. (4) The PSG init writes (A7). (5) Store `03C5` at `$02F0`, the last store of initialization. (6) Enable interrupts and idle in a branch to itself. No interrupt service routine executes in frame 0: the first one executes in frame 1, so frame 0 is not displayed and the first displayed frame is frame 1. The idle loop is the only code that executes between interrupts; the program never halts and never executes `HLT`.

**A6 The interrupt service routine, in this order (every frame from frame 1 on).** (1) The display strobe: a write to `$0020` (the value is ignored); it is the first action. (2) A write to `$0021` (the value is ignored; it selects Foreground/Background mode). (3) Add 1 to the frame counter `$02F1`. (4) Deferred amplitudes: for port 0 then port 1, if its pending word is not `0000`, write pending minus 1 to its amplitude register (`$01FB` for port 0, `$01FC` for port 1) and set the pending word to `0000`. (5) Poll: for port 0 then port 1, read the port, keep the low byte, and compare it with the last-byte word; if it differs, store it as the new last byte, add 1 to the port's change counter (`$02F3` or `$02F5`), write the byte to the port's fine tone period register (`$01F0` for port 0, `$01F1` for port 1) and set the port's pending word to `0010` if the byte is not `FF` and to `0001` if it is `FF`. (6) Render: write the 16 lamp words of A3 for the two last-byte words, port 0 then port 1. (7) The gate: if at least one pending word is not `0000` (a port changed in this frame), write the channel C amplitude register `$01FD` with `000F` when the last byte of at least one port is not `FF`, and with `0000` when both last bytes are `FF`; otherwise do not write it. (8) Re-arm: discard the saved return address (the stack pointer goes back by one), wait a counted delay, enable interrupts and return to the idle loop. The program polls each port once per frame.

**A7 PSG rules.** The program writes a PSG register only in the ways listed here; every write is a CPU write of the stated 16-bit value. Init (frame 0, in this order): `$01F8` mixer `003C`, `$01F4` tone A coarse `0000`, `$01F5` tone B coarse `0000`, `$01FB` amplitude A `0000`, `$01FC` amplitude B `0000`, `$01FD` amplitude C `0000`. Afterwards a register is written only by the interrupt routine: the fine period of a port and the gate in a frame where a port byte changed (A6 steps 5 and 7), and the amplitude of a changed port in the next frame (A6 step 4). The log address of a write is the low nibble of the register address. Model facts the specification relies on (project profile rules PSG-R14, PSG-R15, PSG-R16, tier 4 or inference): mixer bits 0, 1, 2 disable tone A, B, C and bits 3, 4, 5 disable noise A, B, C (1 means disabled), bits 6 and 7 are the port direction bits (clear means input); a channel with both its tone and its noise disabled holds a constant level; the level of a channel whose amplitude register has bits 5 and 4 clear is the register's low four bits; a channel whose amplitude is 0 has level 0 whatever its tone does; the level of a tone-enabled channel with a non-zero amplitude alternates with the tone and its phase is not part of this specification. With the mixer `003C` tone A and tone B are enabled and tone C and all noise are disabled, so channel C is the program's constant-level gate. The tone period of a port is its fine register (the coarse register stays 0), that is the port byte; no tune, no scale and no envelope is used.

**A8 Timing statements a reader may rely on.** A frame lasts 59,736 ticks (14,934 CPU cycles of 4 ticks) and frame k spans the ticks 59,736 k to 59,736 k + 59,735. From frame 1 on, exactly one interrupt service routine executes in every frame; it starts within the first 40 cycles of the frame, its strobe is stamped before cycle 50, its port reads end before cycle 400, its deferred amplitude writes end before cycle 250, its fine period writes end before cycle 400, all 16 lamp words are written before cycle 1,200 and its gate write (if any) ends before cycle 1,300 (all counted from the frame start; the STIC register window of 2,000 cycles and the first BACKTAB row latch at cycle 3,848 both lie later). Consequently the port bytes read by the routine of frame k are the controller state in force at the start of frame k, an event at tick t is first read by the routine of the first frame k with t < 59,736 k, the delivered picture of frame k shows the lamps of the routine of frame k, and a frame is displayed exactly when its routine executed the strobe. Every event of the script lies more than 16,000 ticks from every frame start. The frame counter after the routine of frame k is k, so at a stop tick T that lies at least 10,000 ticks into frame floor(T / 59,736) the counter is floor(T / 59,736).

**A9 The scripted run.** Six controller events, each stating both words (`0x0` means no control closed), then four steps to absolute machine ticks, none of which stops at a halt:

| Event | at_tick | c0 | c1 |
|-------|---------|----|----|
| 1 | 100000 | KEY_1 | 0x0 |
| 2 | 220000 | KEY_1+KEY_9 | 0x0 |
| 3 | 340000 | 0x0 | DISC_E |
| 4 | 460000 | SIDE_TOP | DISC_E |
| 5 | 580000 | 0x0 | 0x0 |
| 6 | 700000 | KEY_1+KEY_9 | SIDE_LOWER_LEFT |

Steps: `run-to` 200000, 440000, 640000 and 806568 ticks. The run delivers the frames whose end tick is at or below the last stop. The PSG write log, the audio samples (one sample every 16 ticks, the 0-based sample i stamped (i + 1) x 16) and the frame slots are captured as `docs/runner.md` describes.

**A10 Not done.** No halt or quit input, no text, no glyph set, no graphics ROM read, no EXEC call, no data table, no moving object, no collision, no delay register, no border or color stack write, no noise, no envelope, no tune.
