## (a) Program specification

<!-- blind-spec-begin -->

The program `ivs-diag-stic-2` is an original cartridge program entered through the project boot stub, contract 2 (cartridge reset entry `$5000`, cartridge interrupt entry `$5004`; the stub hands every interrupt to `$5004` with the interrupt system disabled), with the zero graphics ROM and profile `intv-2609-ntsc-family-p1`. It enables exactly one feature of the picture chip, chosen by a selector, so that each scenario is a single-feature fixture. It has no text, no graphics ROM read, no EXEC call and never halts.

**A1 Selector.** The scenario word `c0` drives the port that a guest reads at `$01FE`. The program reads that port once, in its initialization, keeps the low eight bits of the word read and stores them in `$02F2` (a word with the upper eight bits zero). The selector bytes are `FF` idle (no control closed), `7E` mob, `BE` border, `DE` hdelay, `7D` vdelay and `BD` collision (the controls KEY_1 to KEY_5 of the controller literal); any other value behaves as `FF`. The controllers are never read again.

**A2 Cards.** Initialization writes three graphics RAM cards (a card is 8 pattern bytes, byte y is pixel row y from the top, bit 7 is the leftmost pixel, a bit 1 is a set pixel): card 0 at `$3800` to `$3807` is eight times `FF` (solid); card 1 at `$3808` to `$380F` is `80 C0 E0 F0 F8 FC FE FF` (a staircase: row r has its r + 1 leftmost pixels set); card 2 at `$3810` to `$3817` is `F8 F8 F8 F8 F8 00 00 00` (a block of 5 x 5 set pixels in its top left corner). No other card is written.

**A3 Display.** The display is in Color Stack mode. The color stack registers `$0028` to `$002B` hold 1, 2, 3, 4 and the border color register `$002C` holds 8 (written by every routine except in the selector `BD`, which does not write them). No BACKTAB word advances the color stack, so the background of a card cell is the first stack entry, color 1, for the whole frame. Initialization clears `$0200` to `$02FF` to `0000` (a graphics ROM card 0, foreground 0, no advance: with the zero graphics ROM it shows color 1 everywhere) and then writes the word `0812` at `$0282` (BACKTAB cell row 6, column 10; graphics RAM card 2, foreground color 2, advance clear). The selector `BD` also writes the Colored Squares words `16DB` at `$0285` (row 6, column 13: four quadrants of color 3), `1000` at `$0288` (row 6, column 16: four quadrants of color 0) and `37FF` at `$02BE` (row 9, column 10: four quadrants of color 7). A Colored Squares card whose four quadrants have one color shows a solid 8 x 8 block of it; color 7 displays the color at the top of the stack. BACKTAB is never written after initialization. Card cell (r, c) covers plane positions x = 8 c to 8 c + 7 and y = 8 r to 8 r + 7 (column 19 shows 7 of them); the published plane is 159 x 96 positions, x to the right and y downward from the top left corner.

**A4 Memory map.** `$02F0` init marker (`03C5` once initialization is done); `$02F1` frame counter; `$02F2` selector word; `$02F3` scene number of the last routine; `$0300` to `$0307` and `$0308` to `$030F` the collision read-outs of the routines of frames 3 and 4; `$0340` and up the stack. Every variable is a 16-bit word.

**A5 Initialization (frame 0), in this order.** (1) Write the three cards of A2. (2) Read `$01FE`, keep the low byte and store it at `$02F2`. (3) Clear `$0200` to `$02EF` (the 240 BACKTAB words; `$02F0` to `$02FF` hold the variables and are not cleared). (4) Write the BACKTAB words of A3. (5) Store `03C5` at `$02F0`, the last store of initialization. (6) Enable interrupts and idle in a branch to itself. No interrupt service routine executes in frame 0: the first one executes in frame 1, so frame 0 is not displayed and the first displayed frame is frame 1.

**A6 The interrupt service routine, in this order (every frame from frame 1 on; k is the frame number, equal to the counter after step 3).** (1) The display strobe: a write to `$0020` (the value is ignored); it is the first action. (2) A read of `$0021` (the value is ignored; it selects Color Stack mode). (3) Add 1 to `$02F1`. (4) Choose the scene number s of A7 from the selector and k and store it at `$02F3`. (5) Only for the selector `BD`: in frame 1 write `0000` to each of `$0018` to `$001F`; in frame 3 read each of `$0018` to `$001F`, AND the value with `03FF` and store it at `$0300` plus the register number (`$0018` goes to `$0300`), then write `0000` to each of `$0018` to `$001F`; in frame 4 do the same reads and stores at `$0308` plus the register number and no write. (6) For every selector except `BD`: write `$0028` to `$002B` and `$002C` as in A3. (7) Write the 27 scene words of A7: `$0000` to `$0007` (MOB X), `$0008` to `$000F` (MOB Y), `$0010` to `$0017` (MOB attribute), then `$0030` (horizontal delay), `$0031` (vertical delay), `$0032` (border extension); every word that A7 does not list for the scene is `0000`. (8) Re-arm: discard the saved return address, wait a counted delay, enable interrupts and return to the idle loop. The registers are written by every routine whether or not the scene changed.

**A7 Scenes.** The scene is a function of the selector and k. The listed words are MOB X, Y and attribute (the bits are the rows of `data/video/mob.literal.txt`); the delay words are given where nonzero.

**A8 Hardware rules the program relies on** (project words; the source of each is one community lineage and no rule is a statement about a console; positions are published plane positions, the plane has its origin at the top left, the object field starts 8 positions left of and 8 above it).

- R37 placement. A MOB whose X coordinate (X word bits 7 to 0) is not 0 shows pattern pixel (c, r) at object-field position (X + c, Y + r) (Y is the Y word bits 6 to 0); the plane position is the field position minus 8 in both axes; a MOB with X coordinate 0 is disabled; Y coordinate 0 is not special; positions outside the 159 x 96 plane are not published.
- R38 size. X word bit 10 set doubles the width (each pattern column covers 2 plane columns). The Y size bits (Y word bit 9, bit 8) with the tall bit (Y word bit 7) clear give the displayed height of the 8 pattern rows: `00` 4, `01` 8, `10` 16, `11` 32 plane rows, that is one half, one, two or four plane rows per pattern row. With the tall bit set the 16 pattern rows of two cards cover 8, 16, 32 and 64 plane rows. With X zoom z (1, or 2 when X word bit 10 is set) and p plane rows per pattern row (1, 2 or 4), pattern pixel (c, r) after the flips covers the plane positions x = X - 8 + z c + i (i from 0 to z - 1) and y = Y - 8 + p r + j (j from 0 to p - 1), before the delay of R46. A code with one, two or four plane rows per pattern row is published exactly; the two codes that put two pattern rows into one plane row (tall clear `00`, tall set `00`) are pinned (PD-2).
- R39 flip. Y word bit 10 shows the pattern columns in reverse order, bit 11 shows the pattern rows in reverse order (all 16 rows of a tall MOB); both give the half turn; the zoom applies to each pattern pixel after the flip.
- R40 color and card. The MOB color is the attribute bits 2 to 0 plus 8 times bit 12; the card number is attribute bits 10 to 3 and bit 11 selects graphics RAM (1) or ROM (0); for graphics RAM the card number is bits 8 to 3 (0 to 63); in tall mode card bit 0 is ignored (the upper rows come from the even card, the lower rows from the odd card). A pattern bit 1 is a visible pixel of the MOB color, a bit 0 shows what is behind. X word bit 9 clear hides the MOB (no visible pixel).
- R41 MOB over MOB. Where the visible pixels of two MOBs coincide the MOB with the lower index is shown; the priority bit does not change this.
- R42 MOB over cards. A MOB with the priority bit (attribute bit 13) clear is in front of every card pixel. (A set priority bit is pinned: PD-1; this program never sets it.)
- R44 collision. Register `$0018` plus n bit m (m from 0 to 7, m not n) is set when a set pattern pixel of MOB n and a set pattern pixel of MOB m lie on the same position and both MOBs have the interaction bit (X word bit 8) set; bit 8 of that register is set when a set pixel of MOB n lies on a set background pixel (a card pixel that is a set foreground pixel, or a Colored Squares pixel of color 0 to 6 but not 7) and MOB n has the interaction bit set; the visible bit is not required; a MOB's own bit never reads 1; the bits are sticky until the CPU clears them (a CPU write of 0 clears the register), even when the interaction bit is cleared later; they are computed at the end of each displayed frame k and are readable from the register window of frame k + 1. The solid cards of the collision scenes make a pixel-level reading and a bounding-box reading agree.
- R46 delay. Horizontal delay (`$0030`, 3 bits) h and vertical delay (`$0031`, 3 bits) v move the object field right and down against the displayed area: every card pixel and every MOB pixel is drawn h positions to the right and v positions down of its undelayed position; content moved past the right or bottom edge of the plane is not published.
- R48 border extension. `$0032` bit 0 paints the plane columns 0 to 7 (every row) and bit 1 the plane rows 0 to 7 (every column) with the border color, after cards, MOBs and delay, so everything under a strip is hidden. (The height of the top strip and its place against the delay are pinned: PD-8, PD-9; the frames F-M4 to F-M6 take 8 rows and a place fixed to the display.)
- The picture of frame k is a function of the registers and the BACKTAB as the routine of frame k left them, because the registers are read at the end of the frame (the frame end tick is 59,736 (k + 1)).

**A8a Pinned items (answer `pinned, not derivable`, never a value).** PD-1 a MOB with the priority bit set over card pixels; PD-2 half-height pixels (Y size `00` and tall mode `00`); PD-3 a MOB with X coordinate 0 and collision; PD-4 the border collision bit (bit 9); PD-5 collisions outside the plane; PD-6 collision in a frame with the display off; PD-7 whether a read of a collision register clears it and what a nonzero CPU write stores; PD-8 the height unit of the top strip; PD-9 whether a strip follows the delay; PD-10 the content of the area exposed by a delay with no strip over it; PD-11 a MOB in that area; PD-12 the delay range; PD-13 any dependence of the bus schedule on the vertical delay.

**A9 Timing statements a reader may rely on.** A frame lasts 59,736 ticks (14,934 CPU cycles of 4 ticks) and frame k spans the ticks 59,736 k to 59,736 k + 59,735. From frame 1 on exactly one routine executes in every frame; it starts within the first 40 cycles of the frame, its strobe is stamped before cycle 60, and every register read and write of steps 5 to 7 ends before cycle 1,900 (the register window closes at cycle 2,000; the first BACKTAB row latch is at cycle 3,848). Consequently the picture of frame k shows the registers written by the routine of frame k, a collision bit set by the picture of frame k can be read by the routine of frame k + 1, and a frame is displayed exactly when its routine executed the strobe. The frame counter after the routine of frame k is k.

**A10 The scripted scenarios.** Six scenarios, each a single step `run-to 640000 ticks` with `capture video 0 10`; the run delivers the frames 0 to 9 (frame 10 ends at tick 657,096). `idle` has no input line; the others have one line at tick 0, `input at_tick=0 c0=<control> c1=0x0`, with the control KEY_1 (`mob`), KEY_2 (`border`), KEY_3 (`hdelay`), KEY_4 (`vdelay`) or KEY_5 (`collision`). At the stop the counter `$02F1` is 10 (floor(640000 / 59736)).

**A11 Not done.** No halt, no text, no graphics ROM read, no EXEC call, no priority bit set, no MOB at X coordinate 0 in the collision scenario, no write of a nonzero value to a collision register, no collision from a position outside the plane (the MOB of the `mob` scenario, scene 1, is clipped at the plane edge and no collision scene has a MOB partly outside the plane), no sound.

## (b) Arithmetic (D-03, D-05)

The rules come first and the constants after them. "The routine of frame k" is the interrupt service routine that starts in frame k. A frame cycle is a CPU cycle counted from the frame start S_k = 59,736 k (4 ticks per cycle, 14,934 per frame).

### Placement, zoom and flip

A MOB with X word `x`, Y word `y` has the top left corner of its pattern at the plane position (X - 8, Y - 8) with X = `x` AND `00FF` and Y = `y` AND `007F` (rule R37). With X zoom z (1, or 2 when `x` has bit 10) and p plane rows per pattern row (1, 2 or 4 for the Y size codes `01`, `10`, `11` with the tall bit clear), pattern pixel (c, r) after the flips covers the plane positions x = X - 8 + z c + i (i = 0 to z - 1) and y = Y - 8 + p r + j (j = 0 to p - 1), shifted by the delay (h, v) of rule R46 and then clipped to x = 0 to 158 and y = 0 to 95. X flip replaces c by 7 - c and Y flip replaces r by 7 - r. The staircase card 1 has 36 set pixels (1 + 2 + ... + 8) and the solid card 64, so an unclipped MOB shows 36 z p or 64 z p plane positions: a flip changes where they are, never how many (the conservation check of every frame below). The Y size code `00` is half a plane row per pattern row and is pinned (PD-2); the frames F-M8 and F-M9 use it under the even-line default, where plane row y shows the television line 2 y: the pattern row r of a MOB with top line 2 (Y - 8) is shown by the plane row (Y - 8) + floor(r / 2) when r is even and by no plane row when r is odd.

### Timing and the run bound (lesson 8)

- Window. The register window closes at cycle 2,000 (STIC-R18); the routine's register work ends before cycle 1,900 by the reference sequence below, the first bus window is at cycle 3,791 and the first BACKTAB row latch at 3,848, so no stall is inside the routine.
- Reference sequence, the longest routine (selector `BD`, frame 3), cycles from the cycle table of `data/cp1610/opcode-families.json` as in the Lamp Tone derivation (MVO 11, MVI 10, ANDI 8, MVO@ 9, MVI@ 10, SDBD with MVII 14, DECR 6, INCR 6, a taken branch 9, a branch not taken 7): the first routine instruction at cycle 22 to 30; strobe 11; mode read 10; counter 27; scene choice at most 121; the eight reads with AND and store at most 328 and the eight clears 192; 27 table words as a loop of SDBD with MVI@ (14), MVO@ (9), DECR (6) and a branch (9) = 38 each, 1,026 (a straight sequence of SDBD with MVII and MVO is 25 each, 675): 30 + 11 + 10 + 27 + 121 + 328 + 192 + 1,026 = 1,745, 155 cycles below 1,900 (the straight sequence ends near 1,394). Every other routine is shorter (frame 4 has no clears, the other selectors no reads).
- Re-arm band (rule of the Lamp Tone derivation, section (b)): the `EIS` of the re-arm starts between frame cycle 3,777 and 14,930. With the Lamp Tone form (the routine ends with a drop of the return word and a jump, then a counted delay of N iterations of 15 cycles, then `EIS` and the idle branch) and N = 500 the `EIS` starts at 22 + 700 + 6 + 7,500 = 8,228 at the earliest and 30 + 1,750 + 6 + 7,500 + 13 x 117 = 10,807 at the latest: 4,451 above the lower edge and 4,123 below the upper edge. N = 500 is the reference value; the program author measures the real figures (section (k)).
- Run bound. The step is `run-to 640000 ticks` (default stop `target`). Frame 10 spans 597,360 to 657,095, so the stop is 42,640 ticks into it, 17,096 ticks before its end (at least 10,000), and the routine of frame 10 has finished (it ends by cycle 1,900, tick offset 7,600): the counter is 10. The frames delivered are those whose end tick 59,736 (k + 1) is at most 640,000, that is k = 0 to 9, so `video count == 10` and the capture `video 0 10` holds them all. Frame 0 is delivered and not displayed.
- Settling rule. No frame assert names frame 0 or frame 1 in a scenario with the tick-0 input (the frame of the input and the next one). The scenes of `mob` change at the routine of frames 4 and 7, so the asserted frames 2, 5 and 8 are the middle frame of each scene, one frame from each change.

## (j) Rights checklist and open items for the blind reader

Rights.

- No third-party glyph set, font, picture or pattern: the cards are a solid block, a staircase and a 5 x 5 block, geometric shapes authored here; the Colored Squares words are plain colors.
- No EXEC call and no graphics ROM read (the zero ROM is the project's own 2,048 zero bytes); the program makes no statement about a real EXEC (D11 is not performed).
- No data table other than the scene words, which are register values written in this file.
- No text of any manual, datasheet, wiki page or documentation file is quoted: the rules are restated in the project's own words and the register roles live in the project literal `data/video/mob.literal.txt`; no figure was used (the community wiki STIC page has no MOB register figure).
- The listing is written from this document only: nothing is copied or adapted from another emulator, assembler, test program or title, and no recalled pattern is used.
- Names are functional and brand-free: `ivs-diag-stic-2`, `FX-diag-stic-2`, `diag-stic2-<feature>-pass`; none contains a console, company, product, character or nickname word.
- The run uses only project-made bytes: the stub image, the zero ROM and the program image built from the project's own source; no image is committed.

Open items for the blind reader (readings that rest on one sentence of one source, to be checked or marked unknown):

1. MOB against MOB: the source says a MOB interacts with another MOB without saying pixel or bounding box; the collision rows avoid the question with solid cards (section (d)). A reader who reads one reading as decisive for a row says so.
2. The own bit: the source says a MOB's own bit never reads 1; rows T1 to T4 rely on it only through the bits that are set, and the program writes only zero to a collision register.
3. Sticky across frames: rows T1 to T8 are read in frame 3 after frame 2 moved every MOB apart, which relies on bits staying set until the CPU clears them; rows T9 to T11 rely on the CPU clearing by a write of zero in frame 3.
4. The strips cover MOBs: F-M4 hides the part of a MOB that lies under the strips (the source says the area is blocked out and filled with the border color); a reader who finds the MOB visible through the strip reports it.
5. The place and the height of the strips (PD-8, PD-9) are pinned: F-M4 to F-M6 take 8 rows and a place fixed to the display, the reading that makes the source's stated purpose (the blank areas are never visible) hold for delays up to 7; the reader answers `pinned, not derivable` for any position that depends on either.
6. Where the raw source disagreed with the discussion note (`08-DISCUSS-stic.md` section 2): (a) the discussion note said the own bit is never set; the raw text adds that it also reads 0 when the CPU writes it and that writing bit X of the register of MOB Y does not change bit Y of the register of MOB X; (b) the discussion note called the blank-area color of an unextended delay unknown, while the raw text says the blank area is filled with the background color as the display mode defines it, which names no single color index (so PD-10 stays pinned, with the raw sentence recorded in C110); (c) the discussion note placed the strips' 8-pixel width in a figure-less table, while the raw text states it for both edges in the text and gives only a drawing for the delay at its maximum, which does not give the unit of the top strip; (d) the raw interrupt notes give 13,518 usable cycles per frame at vertical delay 0 and about 13,572 above 0, as the discussion note said (C92 pin). No other disagreement was found.
7. The three coordinates: X 0 disables a MOB, Y 0 is not special, and (1, 1) shows the single lower right pixel of an 8 x 8 MOB at the plane position (0, 0). F-M1 uses the offset of 8 through X = 158 (x0 = 150); a reader who finds a different offset says so.
